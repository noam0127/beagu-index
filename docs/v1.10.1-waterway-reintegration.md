## 단일 게시자 및 독립 체크포인트 읽기 검증
- 기존 worker_next의 통합 작업 hold 응답을 실제 worker에서도 명시적으로 차단하고, 모순된 claim/비정상 응답은 거부하며 이전 로컬 plan 재사용을 차단한다. 기존 workflow와 게시 작업 실행 경로는 추가하지 않는다.
- 독립 private volume의 opaque ciphertext는 저장소 밖 경로, 0700 디렉터리, 0600 단일 링크 파일, 정확한 독립 pin 및 크기와 streaming SHA-256으로 읽기 검증할 수 있도록 후보 모듈을 추가했다. 해시 일치는 암호화 여부, 장기 보존 및 복원 자체의 증거가 아니며 해당 플래그는 false로 반환한다. 실제 저장소/키/백업/관측자 연결은 미구축이다. 기존 128MiB fixture dump 제한은 운영 DB 크기와 같지 않으며 실제 dump 크기를 검증해야 한다. 운영 gate는 유지한다.

## 독립 Google Drive 보관 폴더 및 연결 준비
- 소유자 전용 My Drive 폴더 생성·권한 확인 완료. 실제 폴더 ID, 소유자 permission ID, OAuth 토큰, 암호화 키는 공개 Git 저장소에 기록하지 않는다. 운영 작업자의 별도 OAuth 접근은 미확인. 최소 범위 drive.file 및 해당 앱에 대한 폴더 선택/승인을 우선 검토한다.
- Drive API v3 fixture 연결 후보: owner-only 권한·공유·휴지통·대상 폴더 확인, 기존 AES-256-GCM vault 인증, 고정 Google 업로드 호스트 및 세션 경로 검증, resumable session 단일 PUT, 독립 읽기 권한으로 provider SHA-256 및 원격 byte readback 확인. 오류/불확실 응답 자동 재시도 금지. 실제 백업·전송·복원은 하지 않는다. 실제 네트워크 전송은 미연결이며 프로덕션 dump 형식·크기·키 관리·장기 보존·복원 증명 별도 필요. Drive 자체는 WORM 저장소가 아니므로 independent pin과 별도 보존 정책 필수.
- 공식 API 참조: https://developers.google.com/workspace/drive/api/guides/manage-uploads 및 https://developers.google.com/workspace/drive/api/guides/manage-sharing. fixture-only 제한과 운영 gate 유지.
