# 『난감한 스쿨밴드』 027/030 — 기기 입력 UI 검증 및 실기 미검증 기록

2026-11-23 · 시험 브랜치 `schoolband-playtest` · **코드 구현 / 실제 기기 검증 BLOCKED / CI 성공 미확인**

## 단계 원래 요구사항과 사용자 제한

마스터 계획의 027단계는 Android Chrome, iPhone Safari, PC Chrome/Edge **실제 기기**의 입력·재생·타격음·N레인 동시 처리 증거를 요구한다.

사용자의 명시적 요청에 따라 다음은 절대 시행하지 않는다.

- 학교 교가 편곡·배포의 허락 요청
- 유료 API·서비스 도입 또는 결제
- 음향 확인, 실제 청음, 재생 품질·연주감/타격감 평가

**실제 기기는 이 작업에 연결되어 있지 않다.** 따라서 실제 Android·iPhone·PC의 조작감·오디오·기기별 입력 성공을 검증했다고 주장하지 않는다. Playwright Android Chromium/iPhone WebKit **에뮬레이션은 실제 기기 검증의 대체 증거가 아니다.** 물리 장치·브라우저/OS 버전 증빙은 모두 `BLOCKED / NOT VERIFIED`이다. 사용자의 직접 작업을 요구하지 않는다.

## 코드 변경

- `games/nangam-schoolband-v08/index.html`: 리듬게임 버튼에 한해서 `touch-action:none`을 사용해 터치 중 패닝/화면 확대 제스처가 레인 입력을 선점하지 않게 했다. 페이지의 다른 영역 스크롤과 일반 브라우저 글꼴 확대는 그대로 유지한다.
- 실제 포인터 핸들러는 서로 다른 `pointerId`를 각각 유지하고, 같은 포인터의 반복 `pointerdown`을 막고, `pointerup`/`pointercancel`/`lostpointercapture`와 회전/리사이즈에서 활성 손가락 지도를 비운다.
- `scripts/test-schoolband-stage027.cjs`: 게임 원본의 포인터 처리 함수를 직접 추출하고 **음악 재생 없이** 2포인터 분리·같은 손가락의 중복 차단·해제·언트러스티드 입력·회전 초기화 검사를 수행한다.
- 추가 CI 브라우저 케이스: PC Chromium 키보드, Android Chrome 유사 Chromium 모바일 터치 환경, iPhone Safari에 대응하는 WebKit 모바일 환경. 4악기·3~5레인·포인터·버튼 키보드 활성화·가로/세로 화면 변경·고대비·큰글씨·오버플로·학교 검색·교가 잠금을 DOM/API 목으로 검사한다.
- 테스트의 `AudioContext`는 생성 시 실패하도록 강제로 교체하고 **연주 시작 버튼은 누르지 않는다**. 점수/개인정보를 서버로 POST하지 않는다.
- CI `.github/workflows/schoolband-stage027.yml`: Node 22 문법/포인터 정적검사, 026 20개 차트 데이터 회귀, Playwright Chromium/WebKit 브라우저 검사. GitHub Actions와 실제 브라우저 성공 결과는 아직 **미확인**.

## 7개 역할 검토

1. 리듬게임: 멀티포인터 ID의 입력 분리/반복 차단.
2. 음악·음향: 재생/청음 검사는 금지하고 판정 전에 있는 포인터 전달 경로만 검사.
3. 연출: 손가락 터치 중 OS 스크롤/브라우저 확대 제스처를 패드 표면에서 막도록 CSS 수정.
4. 데이터: 저장소/학교 검색은 mock API 및 로컬 값만 사용하고 운영 DB 쓰기 없음.
5. UX/접근성: 키보드 버튼 활성화·접근성 이름·확대문자·고대비·회전과 모바일 레인 폭.
6. 보안: 디바이스 에뮬레이션을 실기 결과로 가장하지 않음, 교가 미승인 재생 잠금.
7. QA/운영: 실기·오디오 미검증을 명시, 무료 Playwright 브라우저 검증만 CI에 구성, 운영 main/웹/DB 미변경.
