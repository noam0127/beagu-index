## 요약

- 운영 DB의 역사적 학교·연도별 승인 집계는 **7,801건**. **8차에서는 집계 테이블에 신규 데이터 삽입 또는 기존 응답값 수정이 없었다.**
- 원본 학교 식별·동률 모드에 대한 보류 기록은 **2건**으로 유지.
- Lv.1 학교별 문항 집계 전달 구조는 운영 Edge Function 배포 코드와 GitHub 코드를 **바이트 단위 동일**하게 확인했다. 운영 `beagu-level-api`는 **ACTIVE v36**이다.
- 코드 연결에 대한 정적 회귀 검사를 5개 보강했다. 그러나 **실제 로그인 계정으로 브라우저 E2E를 수행한 것은 아니다.**

## 1. 충남 신리초등학교(2023, school_id `8181034`)

2023 원본 `raw_data : 배구지수 시즌1 (2023)`에서 **충남**으로 답한 학교명 `신리초등학교` 3건을 재확인했다. 원본에는 **교육지원청 열이 존재하지 않으며**, 보조 `학교명일치검사` 값도 학교 ID를 확정하지 않는다.

과거 `■011 2023년 배구지수 공개(20240926)`의 `가공완료(20240926)` 시트에는 `충남 / 아산 / 신리초등학교` 학교행이 존재한다. 이 자료의 2023년 앞선 10문항 점수와 원본 충남 신리초 3행의 평균을 점수 변환 방식으로 재계산한 수치는 **10개 문항 모두 일치**한다. 즉 **과거 공개 편집본이 이 3건을 아산으로 집계한 사실은 실증적으로 확인**했다.

다만 과거 편집본의 아산 지정이 **어떤 독립적인 학교 소속 증거로 검수되었는지 확인할 수 없고**, 충남 내 아산·홍성의 동명이교 문제가 사라지지 않는다. 과거 공개되었다는 이유만으로 원본 응답자를 아산 학교에 확정 배정하지 않는다.

추가로 요구되는 근거: 원본 응답의 교육지원청 또는 불변 학교 ID, 원래 담당자의 검수 기록처럼 아산 소속으로 판정한 근거가 명시된 자료.

## 2. 경남 삼성초등학교(양산, 2024, school_id `9151011`)

2024 원본 `raw_data : 배구지수 시즌2 (2024)`에서 `경남 / 양산 / 삼성초등학교`에 해당하는 원본 응답 2건을 확인했다. Q01~Q14를 동일 문항끼리 비교한 결과 **14개 모두 응답 선택지가 서로 달랐고 공통 선택 문항은 0개**였다.

따라서 2개 응답으로 구성된 모든 문항에서 양쪽 보기의 선택 빈도가 동률이다. **단일 최다 선택값이 0개**라는 6차·7차 결론을 재확인했다. 한쪽 값을 무작위 선정하거나, 해당 연도의 평균·기타 학교 자료를 복제하여 `modeOption`으로 기록하지 않았다.

추후 `동률/공동 최다` 상태를 표시하려면 기존 단일 최다 선택값 모델과 구분된 결과 유형 및 별도 공개·소집단 프라이버시 검토가 선행되어야 한다. 이번 단계에서는 미변경.

## 3. 레벨1 API 및 화면 연결 검증

운영 Supabase의 `beagu-level-api` 배포 **ACTIVE v36**의 `index.ts`와 GitHub main `supabase/functions/beagu-level-api/index.ts`가 바이트 단위 동일했다.

코드상 확인된 순서:
1. `X-Beagu-Session` 토큰 형식, 해시값, DB 세션 만료 확인. 세션 없음은 `AUTH_REQUIRED`.
2. `school` 요청에서 `access_level < 1`이면 `ACCESS_DENIED`.
3. `beagu_school_question_aggregates_v2`의 `OWNER_AUTHORIZED_CLOSED_CHOICE`인 2023~2025년 학교별 승인 문항만 읽고, 유효한 `questionId`·`modeOption`·`validRows`를 `schoolQuestionModes` 배열로 정리.
4. `schoolQuestionModes`를 응답에 포함하고, `js/level-search.js`의 상세 펼치기 코드가 `showDetails(...,data.schoolQuestionModes,...)`로 전달.
5. 레벨1 상세 문항 UI가 `modes` 배열을 해당 연도·문항 ID별로 재매핑한다.

레벨1 연결을 검증하는 기존 `tests/school-question-n1-source-restoration.mjs`에 검사항목 5개 추가. **이는 문자열 및 소스 계약 검증이지, 인증된 브라우저 E2E 성공 증명이 아니다.**

7차 신규 3학교의 DB 문항 `13+13+47=73`개에 대해 JSON 필드 형식과 보기 문구 길이를 추가 감사했으며 실패는 0건. 두 집계 테이블 RLS 및 일반 사용자 직접 SELECT 차단 상태도 선행 단계에서 확인함.

## 4. 미완료·다음 단계

- 실제 레벨1 코드/계정으로 로그인한 브라우저에서 각 학교의 역사적 문항이 보이는지 확인하지 못했다. 현 도구에서는 인증 브라우저 세션에 접근하지 못하므로 **그 시험을 통과했다고 주장하지 않는다.**
- 신리초(아산)의 학교 배정은 과거 공개자료에 근거한 역사적 선택으로 남아 있지만, 원본 소속에 대한 독립 검증이 필요하다.
- 삼성초(양산) Q01~Q14의 동률을 단독 최다 선택값으로 저장할 수 없다.
- 단일 응답 기반 학교별 다문항 공개는 차등 노출 및 재식별 위험이 있을 수 있으므로 별도 사전 심사 플래그를 임의로 승인하지 않았다.

**중단 지점:** 추가 식별 증거, 동률 표현 정책, 실제 인증 브라우저 접근이 확보되기 전까지 2개 학교의 새 문항 복구는 보류한다. 8차는 원본 감사·정적 연결 검증·기존 회귀 테스트 보강까지만 수행했다.
