# 『난감한 스쿨밴드』 011/030 — 화성·믹싱 헤드룸·디지털 피크 검증

기준: 2026-11-22 KST. 사용자 원본 `nangam-schoolband_30-step_master_prompt_v1.md` 011/030(원본 045~047)의 **베이스·기타 화성 충돌 점검, 키보드·멜로디 마스킹 방지, 합주 마스터·컴프레서·클리핑/동시타격 피크의 측정 가능한 검증**.

## 실제 소스 변경

### 1. 창작곡 8마디의 화성 관계를 계산 가능한 모델로 고정

곡의 기존 `CHORD_ROOTS` 8개를 보존하면서 `CHORD_SYMBOLS`, `CHORD_ROOT_PCS`, `CHORD_MINOR`, `chordThirdRatio(beat)`, `chordFifthRatio()`, `harmonyAtBar(bar)` 및 `checkMelodyHarmony()`를 추가했다. 진행은 **C–C–G–G–Am–Am–F–C**로, A minor 구간의 3도는 **C 자연음(단3도·3반음)**이며 **C#(장3도·4반음)**을 사용하면 잘못된 코드가 된다.

기존 기타 파워코드가 `root×2.5`로 시작하면 A minor 마디에서 C#이 발생할 수 있었다. 이를 `root×2`의 토닉에 완전5도·옥타브를 쌓는 구조로 수정했다. 기타 업스트럼은 토닉·3도·5도를 **0/17/34ms**에 연주하도록 하고, 키보드 화음 레인 2는 코드별 올바른 3도(Am→C)를 사용한다. 베이스의 루트/완전5도/옥타브 구조는 보존한다.

원래 28음 창작 멜로디의 각 음을 코드의 구성음인지, 장식·경과·7도·9도 성격인지를 **데이터로 구분**한다. 멜로디와 다른 음이라고 무조건 오류로 삭제하지 않으며, 정확한 교가 선율·박자·차트·오디오 판정 시간을 변경하지 않는다. 이는 음악이 모두 같은 코드톤으로만 이루어져야 한다는 과도한 규칙을 피하기 위한 선택이다.

### 2. 파트별 음량 버스·컴프레서

- `MIX_LEVELS`: **master 0.80, melody 0.96, ensemble 0.46, hit 0.80**.
- `melodyBus`: 자동 멜로디를 상대적으로 돋보이게 유지.
- `ensembleBus`: 자동 반주 3악기의 총합이 주선율과 직접 연주음을 지나치게 가리지 않도록 제어.
- `hitBus`: 플레이어가 정확히 친 악기는 자동 반주보다 상대적으로 크게 설정.
- 이 세 버스는 `masterBus`에 합쳐지고, 그 뒤 **DynamicsCompressor(threshold −19dB, knee 14dB, ratio 7:1, attack 0.004s, release 0.20s)**를 거쳐 최종 오디오 출력으로 연결한다.
- 기존 오실레이터·드럼 킥/스네어/하이햇/탐 모두 선택된 버스를 실제 `AudioNode.connect` 목적지로 받도록 개선했다. mute는 `MIX_LEVELS.master`를 기준으로 조절해 이전의 상수 0.82와 충돌하지 않도록 한다.
- `getHarmonyByBar()`, `getMelodyHarmonyAudit()`, `getMixLevels()`로 **읽기 전용 검사 정보**를 제공한다. 사용자 학교명/정답/설문 자료나 오디오 샘플은 업로드하지 않는다.

### 3. 측정 프로토콜

`scripts/test-schoolband-stage011.cjs`는 **실제 게임 HTML에 구현된 오실레이터·노이즈·악기별 `voice`·`scheduleStep` 함수 본문을 추출**하고 브라우저 `OfflineAudioContext`에서 그대로 사용한다. 테스트가 임의로 다른 소리 샘플을 만들어 안전하다고 주장하지 않도록 한다.

- 순수 모델: 8마디 코드 심볼·루트·단/장3도·5도, 28음 원곡의 코드톤/장식음 목록, Am→C자연음 및 잘못된 A장조 인지 실패를 검사한다.
- 원래 차트의 각 코드 마디(8개) × 사용자 선택 악기 4개 = **32개 합주 스냅샷**을 합성한다. 각 스냅샷은 멜로디·다른 3악기 자동 반주와 선택 악기 **최대 2레인 동시타격**을 담는다.
- 모든 PCM 샘플의 절댓값 최고치 `peak`, 제곱평균제곱근 `RMS`, `abs(sample)>=0.999` 클리핑 샘플 수, 비정상 `NaN/Infinity` 샘플 수를 2채널 모두에서 측정한다. 요구사항은 **0 클리핑/0 비정상 샘플, 음성 존재, peak 0.96 미만**. 입력 음원·컴프레서 합주 음량 피크가 이 범위를 초과하면 자동 CI 실패.
- 기타 선택 상황에서 8마디 각각 **멜로디만**/ **자동 반주만** 재합성하여 총 **16개 stem 스냅샷**의 RMS를 비교한다. 단일 버스 계수만 보는 것과 달리 실제 오디오 파형이 너무 작아 듣기 어렵지 않은지도 수치로 확인한다. 최소 비율은 멜로디 RMS/반주 RMS **0.30 초과**(검증 기준이며 사람의 가청성/주관적 밸런스를 뜻하지 않음).
- 별도의 일반 PC·320px 모바일 Chromium에서 게임을 실행해 `AudioContext`에 실제 생성된 **master/melody/ensemble/hit 게인 노드 4개**의 값이 엔진 정의와 일치하는지 확인하고, 5개 난이도·연주 화면 회귀의 손상이 없는지 검사한다.
- 같은 CI에서 기존 010단계 PC/모바일 32개 실제 hit·자동 반주·silent MISS·음소거, 009단계 JSON Schema·오염 차트, 008단계 N레인/20조합, 005단계 판정 경계 회귀 실행.
- 결과 파일 `artifacts/schoolband-stage011/results.json`와 PC/모바일 화면 PNG, 모든 스냅샷의 개별 피크·RMS·최대값을 GitHub Actions 아티팩트로 보존한다.
