## 사용자 작업 절감
- Mac OAuth·AES 키·Docker 재설정이나 합성 업로드 반복 금지. 현재 성공한 합성 증거 재사용(운영 승인으로 승격 금지).
- 합성 handoff CLI는 별도 신뢰 영역의 파일 교환으로만 연결한다. 같은 관리자/계정의 파일 교환은 독립 보안 주체가 아니다. 현재 owner-only Drive와 별도 Google 계정 reader는 양립하지 않으므로 새로운 권한 부여 전 사용자 승인 필요. 대안으로 별도 관리 저장소 또는 승인된 읽기 계정 설계 검토.
- 운영 백업 scope, key custody, retention 및 복구 목표에 대한 운영자 승인 전에 실제 credential 생성/확대·연결·백업·restore·배포·DB 변경 금지. 합성 검증만 진행 가능.
- 운영 연결은 별도 승인 단계로 유지. 현재 production verifier의 backup proof에 별도 freshness/one-time durable ledger 계약이 필요하며 합성 registry를 운영 근거로 직접 사용하지 않는다. 새 코드는 운영 gate/recipe/workflow를 활성화하지 않는다.

## 대용량 합성 스트리밍 후보
- integrated_stream_fixture.py는 별도 합성 scope, 1 MiB AES-256-GCM record, 객체별 256-bit random salt/HKDF-SHA256 derived key, 순번 nonce와 header/index/type AAD, 필수 authenticated final plaintext hash 및 외부 고정 ciphertext/plaintext hash를 사용한다. 8 GiB 설계 상한이며 실제 CI 검증 크기는 192 MiB + 17 bytes의 합성 바이트 스트림이다. 기존 vault 및 운영 검증기는 변경하지 않는다.
- private 0700 디렉터리/0600 파일, no-replace publication, 전체 인증·원본 ciphertext 안정성 확인 전 복원 파일 공개 금지. 정상 오류 시 임시 파일 정리; 강제 종료 시 private 임시 평문이 남을 수 있으므로 운영 적용 전 격리 암호화 디스크 및 crash recovery 정책 필요. 일반 입력 stream은 내부 합성 호출 전용, CLI/실제 DB/원격 전송 없음.
- CI는 대용량 실제 합성 파일 복원·독립 hash 비교, 잘못된 key/pin, chunk 재정렬, 변조, 절단/추가, 초과·부족 입력, overwrite 거부를 검증한다. 이 결과를 운영 exporter나 대용량 실제 Drive 업로드/DB 복원 증거로 인정하지 않는다. 다음 최소 조건은 실제 PG17 합성 dump의 streaming 연결, 대용량 원격 전송 reconcile, 별도 신뢰 주체, 운영 범위/키 보존/복구 목표 승인. 사용자 Mac 재설정 불필요.
