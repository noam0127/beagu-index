## 사용자 작업 절감
- Mac OAuth·AES 키·Docker 재설정이나 합성 업로드 반복 금지. 현재 성공한 합성 증거 재사용(운영 승인으로 승격 금지).
- 합성 handoff CLI는 별도 신뢰 영역의 파일 교환으로만 연결한다. 같은 관리자/계정의 파일 교환은 독립 보안 주체가 아니다. 현재 owner-only Drive와 별도 Google 계정 reader는 양립하지 않으므로 새로운 권한 부여 전 사용자 승인 필요. 대안으로 별도 관리 저장소 또는 승인된 읽기 계정 설계 검토.
- 운영 백업 scope, key custody, retention 및 복구 목표에 대한 운영자 승인 전에 실제 credential 생성/확대·연결·백업·restore·배포·DB 변경 금지. 합성 검증만 진행 가능.
- 운영 연결은 별도 승인 단계로 유지. 현재 production verifier의 backup proof에 별도 freshness/one-time durable ledger 계약이 필요하며 합성 registry를 운영 근거로 직접 사용하지 않는다. 새 코드는 운영 gate/recipe/workflow를 활성화하지 않는다.

## 대용량 합성 스트리밍 후보
- integrated_stream_fixture.py는 별도 합성 scope, 1 MiB AES-256-GCM record, 객체별 256-bit random salt/HKDF-SHA256 derived key, 순번 nonce와 header/index/type AAD, 필수 authenticated final plaintext hash 및 외부 고정 ciphertext/plaintext hash를 사용한다. 8 GiB 설계 상한이며 실제 CI 검증 크기는 192 MiB + 17 bytes의 합성 바이트 스트림이다. 기존 vault 및 운영 검증기는 변경하지 않는다.
- private 0700 디렉터리/0600 파일, no-replace publication, 전체 인증·원본 ciphertext 안정성 확인 전 복원 파일 공개 금지. 정상 오류 시 임시 파일 정리; 강제 종료 시 private 임시 평문이 남을 수 있으므로 운영 적용 전 격리 암호화 디스크 및 crash recovery 정책 필요. 일반 입력 stream은 내부 합성 호출 전용, CLI/실제 DB/원격 전송 없음.
- CI는 대용량 실제 합성 파일 복원·독립 hash 비교, 잘못된 key/pin, chunk 재정렬, 변조, 절단/추가, 초과·부족 입력, overwrite 거부를 검증한다. 이 결과를 운영 exporter나 대용량 실제 Drive 업로드/DB 복원 증거로 인정하지 않는다. 다음 최소 조건은 실제 PG17 합성 dump의 streaming 연결, 대용량 원격 전송 reconcile, 별도 신뢰 주체, 운영 범위/키 보존/복구 목표 승인. 사용자 Mac 재설정 불필요.

## 대용량 PG17 및 전송 계약 연결 후보
- 내부 생성 192행(각 1MiB), 네트워크 차단 PG17, snapshot 고정 pg_dump custom --compress=0을 private 합성 spool로 생성, 128MiB 초과 검증 후 1MiB AEAD 스트리밍 암호화. 원본 spool 삭제 후 모의 원격에서 받은 암호문만 검증·복호화하여 pg_restore stdin으로 새 DB 복원. 데이터별 SHA256/스키마/시퀀스/RLS 비교. 운영 URL, 임의 dump, 외부 키 입력 및 live CLI 없음.
- 모의 Drive resumable 4MiB upload/308 Range ack, 206 range readback, 전체 SHA256 및 소유자/폴더/파일 메타데이터 확인, 실패 시 자동 재시도·부분 파일 공개 금지. 모의 transport만 구현; 실제 Google Drive 대용량 전송 및 불확실 create의 provider reconcile은 미검증. 합성 임시 평문 spool은 private 디렉터리에서만 사용하고 정상 종료 시 정리; 운영용 암호화 디스크/강제종료 복구 정책 필요.
- CI에는 실제 격리 PG17 + 디스크 기반 모의 원격 전송 및 잘못된 ack/readback 거부를 추가. 성공 여부는 공식 CI로 확인한다. 운영 승인·provider 연결·별도 관측자·키 장기 보존은 기존 잠금 유지. Mac 추가 설치 없음.

## 실제 대용량 Drive 합성 검증 준비
- 기존 인증/키/Docker 재사용, `integrated_stream_drive_live_rehearsal.py --oauth-file PRIVATE/oauth.json --key-file PRIVATE/backup.key --confirm-large-pg-fixture-upload` 로 내부 생성 PG17 fixture만 1회 검증할 후보. 기존 key는 권한만 확인하며 별도 임시 키 사용. 128MiB 초과, 200MiB 이하, 정확한 암호문 chunk hash/고정 endpoint/owner-only 확인, 범위별 전송 및 readback 후 격리 복원. 실제 운영 입력·외부 dump·운영 DB 연결 금지.
- 실제 POST 직전 private no-replace large-pg17-fixture-attempt.json 생성. 성공/실패 모두 기록 유지; 재실행·자동 재시도 금지. 불확실 결과는 원격 직접 폴더 목록 확인부터. 임시 키 폐기 후 다시 복호화할 수 없고 장기 보관 증거 아님. 실제 대용량 파일 업로드는 사용자 별도 실행 전 없음.
- Google Drive 공식 resumable/range 계약 참고: https://developers.google.com/workspace/drive/api/guides/manage-uploads 및 https://developers.google.com/workspace/drive/api/guides/manage-downloads . 실제 session URI 호환성 및 provider 응답은 아직 확인되지 않음. 공식 CI는 credential 없는 모의 전송만 사용. 운영 gate 변경 없음.
