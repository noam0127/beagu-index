# v1.11.0 나의 계정 — anonymous account contract

- Only Lv.0, Lv.1, Lv.2. No Lv.3 implementation, teacher verification, social link, email or phone signup.
- Verified survey participation and original device proof establish one anonymous account per canonical challenge visitor. Existing referral credit, participant codes and author ownership are never reset. Existing Lv2 participants can register directly after the same proof.
- Existing canonical Lv1/Lv2 participation code is the sole login identifier (current issuer: 10 characters; retain legacy 18/29-character codes). Internal account UUID remains private. No second login ID. 4+ character password (user requirement; longer unpredictable passwords strongly recommended; server-side rate limiting retained; signup requires a matching confirmation entered locally, never sent as a duplicate credential), separate 13-character uniformly random 32-symbol recovery code (65 bits), displayed 4-4-5, case-insensitive input with optional hyphens. Participation code alone cannot reset credentials or authorize writing. Password proof uses domain-separated HMAC and bcrypt cost 12. Recovery proof uses a distinct HMAC domain; no plaintext credential database storage. Client generates replacement secret before sending so ambiguous network results can be recovered. Successful recovery atomically invalidates prior code/password and all account sessions; reissue the member card. No administrator reset, lookup or email recovery. Lost password plus lost recovery code cannot be recovered through the application.
- Downloadable private member card: login ID, Lv.2 active/inactive at issuance, recovery code. Owner-only account screen shows current server-verified Lv2 status. Do not save secrets in browser storage or analytics; save file explicitly and warn against sharing. No public fixed account identifier.
- Lv.2 writing requires an actual anonymous account session and earned referral, not a transferable participation code alone. Legacy author identity is retained only after device proof; suspended historical accounts cannot bypass moderation. Existing read permissions remain.
- Ten random barcode glyphs I, l, |, ǀ, ❘, ı, ∣, │. Private preallocation 500/minute, Monday 00:00 KST simultaneous selection, old posts anonymous, no old/future alias API. Existing weekly uniqueness and 100k benchmark retained.
- Survey/participant visitor relationship is still present in private database. Legacy Auth and SMS data and infrastructure logs may permit identity inference. Database owner can correlate records or alter application. Do not advertise absolute administrator-proof anonymity. Before any release, separately audit survey identifiers, referral data, IP logs, historical Auth/phone retention, access separation, backups and deletion policy. No production data removal, OAuth config or DB modification authorized by this candidate.
- Before production, explicitly approve isolated Edge gateway configuration, secret provisioning, historical migration/privacy review and deployment. No provider credentials, no Lv.3.
