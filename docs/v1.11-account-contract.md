# v1.11.0 나의 계정 — identity contract

The existing challenge visitor and referral record remain the canonical source of earned access.
Do not copy, reset, or inflate referral credit. A participation code is not a password.

- Provisional account: one verified challenge visitor per account, random account identifier, password credential handled by a dedicated secure authentication path. No plaintext passwords, shared-code login, email guessing, or identity transfer from client metadata.
- Lv.1: existing verified participation. Lv.2: earned referral entitlement, checked server-side at use. A password or OAuth login alone grants neither.
- Formal account (Lv.3): link verified Auth identity to the original visitor with fresh ownership proof; no new challenge enrollment for existing users. Never automatically grant an exception to the referral requirement; policy for existing Lv.1 is not yet finalized.
- Preserve original device proof, existing Post-it author identity and historical referral records. Resolve conflicting links by denial, never overwrite another user's account.
- Google, Kakao and Naver are separate provider integrations; only expose providers after verified configuration. No provider setup, secrets, live data migration or live deployment is authorized by this development branch.
- Public display nickname: ten randomly allocated characters from I, l, |, ǀ, ❘, ı, ɪ, │, ┃; no digit 1 or mathematical divides symbol U+2223 (∣), no user-controlled nickname, no account identifier, email or original visitor ID. Uniqueness uses exact character identity.
- Password setup: after survey submission, Google Forms displays a link to the web account setup page. Never request or store passwords in Forms or Sheets. A common completion link is not proof of submission: require verified participation and original device ownership before setting a password. Password length remains at least 12 characters.
- Account linkage must be atomic, one-to-one, idempotent, rate-limited, revocable and audited. Account recovery must not allow takeover by code alone.
- Existing Lv.0–2 flows remain available throughout migration; formal account integration is additive.
