# 『나의 OO한 학급일지』 36화 선택·관계·학교 분기 P0

## 상태
- 기준 코드: `js/class-diary-semester-long-v3.js`, `js/class-diary-world-v1.js`.
- **추가한 파일**: `js/class-diary-branch-map-v1.js` (36화, 108개 선택지, 16개 선택 회수)
- 테스트: `node scripts/test-class-diary-branch-map.cjs`
- 이 변경만으로 운영 중인 게임의 원고와 선택 화면은 바뀌지 않는다. 기존 사용자 저장을 훼손하지 않기 위한 분리 단계.

## 메커니즘
1. `episode(n)`: 회차 제목·등장인물·학교 환경 키·3개 선택지.
2. `branch(history)`: 저장된 `{episode, choice}` 배열로 전체 선택 플래그·결과값 재생성. **현재 서버 저장 스키마 변경 불필요.**
3. `memories(history, target)`: 앞선 선택에 따라 달라지는 대사 복선.
4. `schoolContext(world,n)`: 공개 승인된 학교 공식 지표만 연도와 함께 반환. 미확인 지표는 `missing` 처리.
5. `settingVariant(world,n)`: 규모별 배경 연출 힌트. 특정 학교의 교직원·학생의 성격, 사고율, 보호자 사정을 예측하지 않음.

## 단계별 통합
- **P1** `js/class-diary-prose-act1-v1.js`~`act6-v1.js` 및 장편 원고를 새 36화 구성에 맞춰 재작성한 뒤, `BeaguClassDiarySemester.chapter()`에서 데이터 파일의 선택 문구를 소비한다. 화면 표시 문구와 선택의 효과가 반드시 같아야 한다.
- **P2** `choose()`의 기존 공통 `EFFECTS`를 회차별 `effect`로 교체한다. 기존 저장 파일은 변경하지 않고 `history`에서 선택을 재구성하며, 기존 버전의 플레이를 이어갈 때 과거 능력치를 함부로 다시 계산하지 않는다.
- **P3** `BeaguClassDiaryWorld.generateWorld()`의 승인된 지표에 한해 `schoolContext()`를 연결한다. 실제 학교의 평면/안전사고/학생 개인 사정은 절대 추정하지 않는다.
- **P4** 엔딩은 기존 5종 기본형을 유지한 채 관계별·사건별 회상을 추가한다. 연애 상태는 초기 프로필에서 별도로 설정하여 기존 애인 이야기와 충돌하지 않게 한다.
- **P5** 기존 회귀테스트와 더불어 36화×3선택, 저장/불러오기, 누락 학교 지표, 개인정보/민감 설정, 2027 허구 표시를 검증한다.

## 일관성 점검이 필요한 사항
- 스승의 날 케이크 21등분은 서사적 고정 숫자다. 실제 선택 학교 평균 학급 인원으로 덮어쓰지 않는다.
- 학교 급식·우유급식 운영은 기준 연도 정보이지 2027년의 사실이 아니다.
- ㅗ자형 교사, 중앙의 큰 교장실, 1층 장미반은 고정된 가상 학교 연출이다.
- 아동의 이혼 가정/장애/국적/풍선 공포/가정 사정은 학교 지표에서 생성하지 않는다.
- 실수, 사고, 책임, 사과는 플레이어의 인격에 대한 낙인 점수로 표현하지 않고 이야기적 결과로 연결한다.


## 매일 학급일지 기록 선택 (2026-11-20 신규 콘셉트)
- 하루 이야기 → **행동 선택** → 사건 결과 → **오늘의 학급일지 3문장 중 1개 선택** → 다음 회차.
- `js/class-diary-daily-journal-v1.js`: **36일 × 3개 = 108개 기록 문장**, 이전 행동 선택과 분리.
- `teacher-class-diary-play.html`: `semester_reflection` 화면에서 기록 문장을 고른 후에만 '다음 회차' 표시.
- 기록은 `state.journal: [{episode, choice}]`로 선택 번호만 저장, 기존 `history` 구조와 `version`은 그대로 유지. 불러온 구버전 저장에는 `journal` 필드가 없더라도 다음 기록 선택부터 생성됨.
- 기록 문장은 사실을 바꾸지 않고 주인공이 같은 하루에서 무엇을 중요하게 기억하는지만 결정.
- 36화 엔딩에 마지막으로 선택한 학급일지 기록 3개를 다시 보여 줌.
- 저장 전환 검사: 기존 Supabase `class-diary-progress-v1`은 추가 `journal` 필드를 명시적으로 거절하지 않음. 다만 **운영 End-to-End 저장/불러오기 테스트는 추가로 필요**.
- 기록 선택 UI의 세 가지는 정답/오답 점수로 매기지 않는다.
