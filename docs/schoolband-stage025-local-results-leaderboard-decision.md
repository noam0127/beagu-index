# 난감한 스쿨밴드 025/030 — 결과 화면·기록 이상 감지·선택적 순위표 결정

2026-11-23 · **구현 반영 / Node·Chromium CI 통과는 미확인**

## 1. 서버 순위표 최종 선택: 이번 버전에서 보류

이 단계는 마스터 프롬프트의 "선택적 순위표·비정상 기록 검증·결과 화면"에 해당한다. 서버 순위표는 **현재 채택하지 않는다**. 사용자나 학생의 닉네임·계정·학교·점수·활동 패턴을 서버에 수집할 필요가 없으며, 브라우저 로컬 기록은 사용자가 직접 조작할 수 있어 전국 순위로 제시하기에 충분히 공정하지 않기 때문이다.

- 백엔드 순위표 API, 서버 쓰기, RLS 테이블, 속도 제한 등의 구현은 **미채택**. 서버 순위표 도입을 선언하거나 구현했다고 주장하지 않는다.
- 점수는 브라우저 `localStorage`에서만 읽고 저장한다. `schoolband-school-read-v1` 공개 GET은 학교 검색에만 사용하며 점수/닉네임 등의 개인정보를 전송하지 않는다.
- 로컬 저장소 값은 부정하게 변경할 수 있으므로 본 버전의 기록을 전국 경쟁·공식 순위·학생의 성취도로 해석하지 않는다.
- 향후 서버 순위를 다시 채택하기 전에는 인증 방식, 봇·위조 방지, 프라이버시, 연령 적합성, 취약점·RLS·속도 제한의 실제 요구를 별도로 검토해야 한다. 이번 단계에서는 진행하지 않는다.

## 2. 공연 결과 화면

- 게임의 완료/중단 시 결과 카드에 **이번 점수 / 정확도 / 최대 콤보** 세 지표를 크게 표시한다.
- 완료 시 PERFECT/GOOD/MISS 세부 정보도 표시한다.
- 중단 시에는 그때까지 판정된 노트의 정확도만 참고용으로 보여주며 최고 기록에 반영하지 않는다.
- 비정상 또는 미완료 판정은 '결과 검증 실패'로 표시하고 점수 수치를 숨긴다. 최고점 기록 저장을 차단한다.
- 새 학교/곡/악기 선택과 새 연주 시작 시 결과 카드가 초기화되도록 하였다.
- 독립된 `aria-live` 결과 영역, PC/모바일 대응 3개 지표 패널 및 개인정보 보존 문구를 사용한다.
- 이번 결과 카드는 서버 순위·전국 학교 비교·개인 식별 정보를 표시하지 않는다.

## 3. 비정상 기록 정책

`concertSummaryModel`과 `validScoringResult`에서 다음을 검사한다.

- 점수/노트 수/콤보/판정 수의 정수 여부와 정상 범위
- `perfect + good = hits`, `hits + miss = judged`, `judged <= total`, `bestCombo <= hits`
- 점수 하한 `1000 × perfect + 600 × good`, 상한 `1500 × perfect + 900 × good`
- 완주 기록: 전 노트 판정 완료, 곡 선택이 지원되는 기존 자체 창작 연습곡
- 중단 기록: 표시만 허용, 최고 기록에 저장 불가
- 미등록 교가/허위 곡 종류/정수 아님/부정확한 판정/과다 점수: 결과 숨김 및 저장 불가

이 정책은 우발적인 잘못된 데이터와 일부 비정상 값을 거르는 **클라이언트 유효성 검사**일 뿐 강력한 부정행위 방지 시스템은 아니다.

## 5. 7개 전문가 역할 검토

1. **리듬게임:** 노트 결과를 점수·정확도·콤보 중심으로 요약하고, 중단의 정확도를 완주와 구분.
2. **음악/음향:** 실제 음향·청음·연주감 평가는 사용자가 제외했으므로 수행하지 않고 결과 모델만 검증.
3. **연출:** 간결한 3개 결과 지표, 성공/중단/실패 상황별 분명한 문구.
4. **데이터:** 서버 순위표 미채택, 기록은 사용자 브라우저 로컬에만 보관.
5. **UX/접근성:** 작은 화면 그리드, 읽기 쉬운 숫자, 재선택 시 결과 숨김, 접근성 상태 설명.
6. **보안/개인정보:** 점수·닉네임·학생 정보 업로드 없음, 로컬 위조 한계 명시, 비정상 기록 필터.
7. **QA/운영:** 예외 입력 테스트, 화면 검사 계획 및 CI 정의, 운영 사이트와 DB를 수정하지 않음.
