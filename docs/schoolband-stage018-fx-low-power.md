**근거:** 사용자 제공 `nangam-schoolband_30-step_master_prompt_v1.md`의 **018/030(원본 068~070)**. 실행일 2026-11-22 KST. 저장소 `noam0127/beagu-index`의 `schoolband-playtest` 시험 브랜치에만 적용하고 운영 `main`, `baeguindex.com` 및 운영 Supabase DB/Edge Functions, 기존 순위/학교 데이터를 수정하지 않는다.

## 1. 코드에서 확인한 문제

기존 게임에는 사용자 `효과 줄이기`, 진동 체크, 음량 0~100%, OS prefers-reduced-motion, 60개 이내 파편의 상한이 존재했다. 하지만 60fps마다 그라데이션과 그림자를 그리는 Canvas 렌더링, 최고 60개의 움직이는 파편·짧은 화면 흔들림은 저사양 기기에서 비용이 높을 수 있었다. **지연의 원인이 판정 시계인 것은 아니므로, 고비용 연출만 낮춰야 한다.** 실제 운영 사이트나 기기별 배터리 성능을 측정하지 않은 상태에서 절대 FPS/절전량을 주장할 수 없다.

## 2. 실제 구현과 처리 규칙

- **저사양 모드:** `#lowPowerFx` 사용자 체크박스 추가. `#fxModeStatus`의 `aria-live=polite`에서 현재 설정이 기본/저사양/움직임 최소화인지 문구로 안내한다. 기존 `nangam-band-fx-v1` 로컬 설정에 `lowPower` boolean을 더해 `reduce`, `vibration` 사용자 설정과 함께 재시작 후 보존한다.
- **오디오 판정 우선:** 매번 `requestAnimationFrame(animate)`에서 기존 `AudioContext.currentTime`을 읽고 노트의 MISS/PERFECT/GOOD을 기존 함수로 판정한다. 저사양 모드에서 **오로지 비싼 `draw()`를 32ms(최대 약 30fps 목표) 간격으로 제한**한다. 음악 반주 예약 `setInterval(scheduleAhead,30)`, 실제 키 입력 `hit()`, 점수/콤보/노트 `done` 상태는 모드별로 변경되지 않는다.
- **Canvas 최적화:** 24px 판정 노트의 레인·위치·굵기·흰 테두리는 유지하면서, 저사양에서 매 노트의 그라데이션/그림자를 단색으로 교체하고 화면 흔들림·ring/combo 애니메이션을 줄인다. PERFECT 파편 수는 11개→3개, GOOD은 6개→2개이며 글로벌 파편 상한을 60개→**12개**로 줄인다.
- **움직임 최소화:** 기존 `prefers-reduced-motion`과 사용자 `reduceFx`는 연출 최소화 정책에서 저사양보다 우선하며, 파편 0·진동 0·움직이는 CSS 애니메이션 0. 기본적인 판정 문자 PERFECT/GOOD/MISS는 남아있어 색깔이나 흔들림 없이 확인할 수 있다. OS 설정이 강제된 경우 임의 해제하지 않도록 기존 제약 유지.
- **진동:** 사용자가 동의해 켠 기본 모드에서만 `navigator.vibrate`를 사용한다. 저사양 또는 움직임 최소화 모드에서는 진동 호출이 나오지 않도록 별도 보호한다. 브라우저가 진동 API를 지원하지 않아도 예외를 처리하고 연주를 계속할 수 있다.
- **음량:** 기존 Stage012의 0~100% 음량 설정·음소거와 별도. 시각 효과 모드 변경이 마스터 게인, 음향 미터, 실제 노트 판정과 간섭하지 않는다.
- **측정 진단:** 읽기 전용 `getPerformanceFx()`로 전체 실행 중 `judgementFrames`, `renderedFrames`, `skippedVisualFrames`, 실제 적용 `mode`, `maxParticles`, `vibrationEnabled`, `volumePercent`, 실제 시계의 명칭을 반환. **절전 와트/배터리 수명은 추정하거나 기록하지 않는다.** 새 게임마다 판정·그리기 수치를 초기화해 과거 연주와 혼동하지 않는다.
