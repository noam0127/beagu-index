# Cloud Run isolated verifier — review only
- Generate a new context: node docs/run4-ranking-preflight/cloud-run/prepare-context.cjs /tmp/run4-context
- Build locally: docker build -t run4-fixture /tmp/run4-context
- Run ONLY in isolated CI, with a dummy 64-hex HMAC and no external networking; use loopback and smoke.cjs.
- Planned production settings: 1 vCPU, 2 GiB RAM, min instances 0, max 2, concurrency 1, request timeout 60s. Private IAM, no allUsers grant, dedicated invoker identity and secret. App HMAC is defense in depth, not a replacement for IAM. No Google project or credentials are created.
- Worker receives only seed/difficulty/replay/elapsed. No production config, database or user identities. Synthetic page is never public. Pin artifact revision and exact image digest after the build; existing pinned Playwright 1.56.1 is for parity, assess browser security before production. The lockfile pins direct package and registry URL; obtain and verify registry integrity in CI before promotion.
- Supabase-side bridge uses server-owned session table and earned Lv2 check, school lookup, signed request and private service-only RPC. SQL stays outside migrations. Actual Edge entrypoint and Google-issued ID token provider (workload identity or narrowly scoped approved credential) are deliberately not enabled. Reject unavailable verification. Do not expose worker publicly to bypass IAM.
- Quota: 300 attempts per KST day global, 10 per actor. Shared Lv1 code permits new session issuance, so per-token quota is not a per-person guarantee. Global quota still bounds cost. Admin exclusion is enforced when admin bearer is provided; anonymous shared-code identity cannot prove a person isn't an administrator. Review these limitations before official release. Retention/cleanup and retry policy still need review.
