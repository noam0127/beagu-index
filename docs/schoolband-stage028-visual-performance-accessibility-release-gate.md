## 기존 단계 028의 완료 요건과 범위 조정

마스터 028은 프레임률·CPU/메모리·오디오 끊김·긴 플레이 피로·광과민·소음, 저성능 모드 판정 불변성과 치명/높음 결함 제로를 요구한다.

여기서는 **실제 연주나 오디오를 재생하지 않고** 정적 캔버스 그리기 비용, 접근성 상태 및 화면 제스처/효과를 검사한다. 따라서 실제 연주 중 FPS, CPU·메모리 최대치, 기기 오디오 끊김/소음, 장시간 연주 피로는 측정하지 않았고 완료를 주장하지 않는다.

  - 저사양 모드의 문구를 '판정 계산 유지'로 변경했다. 실제 소리 동일성은 테스트하지 않았으므로 이를 보장한다고 표기하지 않는다.

  - 마지막 120회 시각 캔버스 그리기 비용의 평균/p95/최대치만 보관하고, 대기 화면에서만 `staticVisualBenchmark(1..60)`을 호출할 수 있게 했다. `AudioContext`를 생성하지 않고 점수/기록·권한을 바꾸지 않는다.
- `scripts/test-schoolband-stage028.cjs`: 실제 게임 파일의 시각 성능 순수 함수를 추출하여 기본/저사양 프레임 예산, 표본 중앙화 및 상한 메모리 캡, 초점·감소 효과 CSS와 게임 보안 상태를 확인한다. 또한 1280×800, 390×844, 320×640 화면에서 오디오를 차단한 DOM·정적 캔버스 측정, 초점 링·고대비·큰 글씨·효과 줄이기, UI 가로 스크롤, 기록 불변성과 점수/개인정보 서버 미전송 여부를 시험하도록 구성.

### 데이터 해석주의

- `static_canvas_draw_only`의 p95는 **연주하지 않는 상태의 정적 캔버스 단일 draw 비용**이다. 사용자의 실제 기기 FPS 또는 CPU 사용률, 체감 연주 성능이나 오디오 지연이 아니다.
- 보고용 16.7ms는 60fps 참고 프레임 예산이다. 이보다 빠른 정적 그리기 자체가 실게임 60fps 보증은 아니다. 수치가 미확인인 현재에는 '성능 양호' 판단을 내리지 않는다.
- Chromium `performance.memory`가 있는 경우에만 비공식 JS 힙 사용량 차이를 기록한다. 실제 물리 기기 메모리 소비량/최대치를 보증하지 않는다.
- 연주 시작 클릭을 하지 않는다. 브라우저 테스트는 `AudioContext`와 `webkitAudioContext`를 생성 시 예외 발생 클래스로 교체한다.

## 가상 전문가 7개 관점의 검토

1. **리듬게임**: 시간·판정 루프를 변경하지 않고 시각 렌더링 여부만 분리, 구분된 노트·점수 계산을 유지.
2. **음악·음향**: 사용자 요청에 따라 청음·오디오 측정 미수행; 게임 음악은 허용된 내부 창작 데이터로 제한.
3. **연출**: 점멸·위치 이동 효과 최소화 옵션과 저사양 프레임 예산, 눈에 띄는 초점 표시.
4. **데이터·성능**: 120개로 상한된 시각 표본, 통계 p95와 선택적 힙 사용량, 사용자/학교 식별값 없는 QA 보고서.
5. **UX·접근성**: 작은 화면·고대비·큰 글씨·키보드 단계 이동, 3개 화면 크기 회귀 계획.
6. **보안·윤리**: 미승인 교가/전국 리더보드 잠금, 실제 성능 미측정 오인 방지, 운영격리.
7. **QA·운영**: HIGH 결함을 공개 상태로 기록; CI 로그·시험 웹·실기 게이트가 확보되지 않아 '제로 결함' 출시 승인 불가.
