- 기존 MFA/manifest/recipe 검증과 OIDC worker 검증 재사용, production 전용 audience와 명시적 env gate, 별도 registry, 고정 workflow SHA. Python scoped runner와 생산 제어 ledger 연결 구현. 운영 transport는 미연결이며 실제 worker/publisher wiring, provider 및 durable backup/observer는 추가 준비 필요. 기존 단일 Pages publisher 미변경. UI 잠금 유지. CI에서 실제 disposable PostgreSQL 설치 실패/기본 잠금/권한/claim/backup/실패 중단을 검사한다. 운영에 설치하거나 활성화하지 않는다.

## 운영 백업 증거 및 기존 Pages 공급자 연결 후보
- 운영 실행기의 backup 단계는 독립 Ed25519 관측자 서명, 정확한 job/base/candidate/plan 및 durable encrypted checkpoint, 전체 범위 digest, 원본·격리 복원 fingerprint 일치와 원본 보존 증거를 추가로 검사. 합성 fixture proof는 테스트만 사용; 실제 운영용 backup exporter, durable object store/KMS, 전체 schema/extension 및 외부 의존성 복원 증거는 미확보. 단순 fixture 성공 플래그로 진행하지 않음.
- 승인된 Pages 파일 묶음과 overlay/stamp/tar SHA를 기존 ProviderAdapter의 단일 게시 API 및 live byte readback에 연결. upload artifact ID/digest와 tar SHA는 구분하고 별도 신뢰된 승인 요구. .nojekyll은 HTTP 관측 대상에서만 제외. 운영 제공자 transport 잠금 유지. 기존 CI에서 실제 disposable PostgreSQL 및 mock provider 단일 POST/관측을 검증하도록 추가. 실제 workflow 업로드, credential, observer provisioning, backup exporter와 운영 실행 진입점은 미완료. 별도 승인 전 실행 금지.
