# 배구지수 개발 → 버전 생성 → 시험·운영 배포

## 소스와 배포는 분리합니다

- GitHub: `noam0127/beagu-index`, 기본 브랜치 `main`
- 개발 작업: ChatGPT가 기능별 브랜치와 PR로 변경사항을 제출합니다.
- '개발 작업함': 공개 GitHub PR의 진행 중 작업을 표시하고, `main`에 병합된 새 커밋의 제목과 변경 파일을 자동 조회합니다.
- '버전 생성': 관리자가 버전명과 수정 요약을 입력하고 버튼을 눌러 그때의 `main` 커밋 SHA를 불변 스냅샷으로 등록합니다. 다른 대화의 새 작업이 끼어들면 생성이 거절되고 목록을 새로 확인해야 합니다.
- '시험 웹': 등록 버전 중 하나를 선택하여 `https://baeguindex.com/_preview/`에 반영합니다.
- '실제 웹': 시험 배포 이력이 있는 등록 버전만 선택할 수 있습니다. 관리자가 시험 검증 후 추가 확인해야 `https://baeguindex.com/`에 반영합니다.
- 모든 배포와 롤백은 서버가 기록하고, 완료 시점에 실제 적용 SHA가 갱신됩니다. GitHub main 병합만으로 운영 웹이 변경되지 않습니다.

## 매번 ChatGPT에 보내는 개발 지시서

```
배구지수 웹개발
작업명: [간단한 제목]
수정내용:
- [변경 1]
- [변경 2]

요구사항:
1. 기존 main 및 관련 파일/PR을 먼저 확인하고 중복 작업하지 마.
2. feature 브랜치에서 구현하고 테스트한 뒤 PR을 만들어.
3. 작업명과 변경 요약을 PR 제목·본문·커밋에 남겨 관리자 개발 작업함에서 확인할 수 있게 해.
4. GitHub main에 머지하는 경우에도 시험 웹과 실제 웹은 직접 배포하지 마.
5. 배포 버전은 관리자 업데이트 페이지의 '버전 생성' 버튼을 눌렀을 때만 만들어.
6. 운영 DB와 Supabase Edge Function의 변경은 별도 위험을 확인하고, 관리자 승인 없는 변경을 배포하지 마.
```

## 버전 규칙

`MAJOR.MINOR.PATCH` (예: `1.2.0`):
- PATCH: 문구·배치·오류 수정
- MINOR: 기능 추가
- MAJOR: 호환성을 바꾸는 큰 개편

버전 생성은 연속된 커밋 범위를 한 번에 고정합니다. **서로 의존성이 있는 PR을 임의로 체크박스 선택해 조합하는 기능은 제공하지 않습니다.** 일부 기능만 묶고 싶다면 별도 feature 브랜치에서 선별하여 `main`에 병합하거나 스냅샷 브랜치로 따로 구성해야 합니다.

## 운영 주의

현재 시험 웹은 `baeguindex.com/_preview/` 경로를 쓰며 운영 Supabase에 연결됩니다. 그러므로 시험 중 설문 제출, 글쓰기, 계정 생성, 관리자 데이터 변경, 실제 문자 발송 등은 운영 데이터에 영향을 줄 수 있습니다. 장기적으로는 **별도 Supabase staging 프로젝트, 테스트 데이터, 전용 API 키**로 물리적으로 격리해야 합니다.

Supabase 마이그레이션이나 Edge Function은 GitHub Pages HTML/JS와 다르게 운영 서버를 직접 바꿀 수 있습니다. 이번 관리자 버전 카탈로그도 마이그레이션과 Edge Function이 적용되어야 동작합니다. 해당 작업들은 별도의 테스트와 명시적 승인 후 배포합니다.
