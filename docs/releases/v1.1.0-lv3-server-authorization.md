# 배구지수 v1.1.0 — 19단계: Lv3 서버 인가·권한 발급·만료

**2026-11-22. 상태: 개발 브랜치 코드/독립 PostgreSQL 16·CI 검증 완료. 실제 회원 권한·운영 DB·시험 DB·운영/시험 웹 미변경.**

## 권한 판정 규칙

1. **Lv0**: 2026 원본 설문 참여 검증이 없는 고유번호 발급자. 2026 코드 발급만으로 Lv1이 되지 않음.
2. **Lv1**: 2026 원본 응답이 승인된 **동일 고유번호**. 추천 없음/심사대기/철회면 Lv1만.
3. **Lv2**: 본인 설문 승인 + 중복/품질검사에서 승인된 유효 추천 1건 이상 + 활성 추천 프로필.
4. **Lv3**: **서버에서 확인한 Lv2** + 18단계 **원기기-Auth 계정 독점 연결** + 인증된 현재 Supabase Auth 사용자·실제 활성 Auth 세션 + **관리자 승인된 Lv3 릴리스 스위치** + **30분 만료/취소 가능한 서버 발급 토큰**. 코드 소지, 브라우저 레벨 배지, Auth 회원가입 버튼만으로 승급 불가. 2026 추천/원본 응답이 취소되면 이미 발급된 Lv3 토큰도 재검증 때 거절.

기존 `beagu-level-api`의 참여코드 기반 Lv0–2 인증과 `beagu_level_sessions`은 수정하지 않았다. **Lv3는 참여코드 자체의 등급을 3으로 올리지 않고 별도 Auth 계정 세션과 결합한 서버 권한**으로 구현했다. Lv3 등급이 앱 UI에 자동 표시되거나 보호 데이터가 개방되지는 않는다.

## 구현 결과

### 1. 서버 전용 권한 원장 및 긴급 차단 스위치

`supabase/migrations/20261122002000_beagu_lv3_server_authorization_v1.sql`

- `beagu_private.lv3_release_control_v1`: **설치 직후 `enabled=false`**. 임의의 회원·브라우저·일반 Edge API로 활성화 불가. 권한 있는 DB 릴리스 승인 절차와 승인자·시각·20자 이상 이유 없이는 ON 불가. 서비스 역할의 일반적인 UPDATE 권한도 부여하지 않음.
- `beagu_private.lv3_member_sessions_v1`: 원문이 아닌 **SHA-256 해시 토큰**, Auth 사용자 UUID, 2026 참가자 UUID, 실제 Auth 세션 UUID, 발급·만료·철회 시각만 저장. Lv3 세션은 **최대 30분**. 회원 이메일, 비밀번호, 전화번호, 설문 응답·개별 고유번호 문자열, JWT 원문, 기기 비밀값을 저장하지 않음.
- `public.beagu_lv3_issue_session_v1`: 서비스 역할만 호출. 릴리스 ON, 16단계 Auth 활성 세션, 17단계 본인 설문·추천 품질, 18단계 계정 독점 링크를 모두 검증. 계정당 **1시간 6회**까지만 발급; 재발급 시 이전 세션을 즉시 철회.
- `public.beagu_lv3_verify_session_v1`: 매 이용 시 글로벌 스위치·토큰 해시·사용자 UUID·Auth 세션 UUID·2026 참가자 UUID·실제 현재 Lv2 품질·계정 연결 상태·만료·철회 여부를 다시 검사하는 **서버 권한 확인 함수**. 향후 Lv3 전용 데이터 API마다 이 서버 검증을 호출해야 하고 UI 배지 자체를 신뢰해서는 안 됨.
- `public.beagu_lv3_revoke_session_v1`: 본인 Auth 세션의 임시 Lv3 토큰만 철회. 링크 소유권/추천 실적·작성자 UID는 유지.
- 관련 테이블 RLS 활성화, `anon/authenticated` 직접 접근 차단. RPC는 서비스 역할에만 EXECUTE. 전용 데이터 공개 정책은 향후 릴리스 단계에서 별도 구현·검증.

### 2. Edge API와 전용 브라우저 클라이언트

`supabase/functions/beagu-lv3-member-api-v1/index.ts`

- POST `issue`, `verify`, `logout`만 허용. **Supabase Auth `auth.getUser(jwt)`로 신원·이메일 인증을 검증**, 토큰의 `session_id`와 실제 `auth.sessions` 활성 상태를 16단계 RPC로 확인.
- 별도 `X-Beagu-Level-Session` 헤더의 2026 참여코드 세션을 서버 DB에서 찾고 17단계 현재 **Lv2** 여부를 재검증; 익명·다른 계정·미인증/만료 세션·추천 자격 취소 시 실패.
- CSPRNG 32바이트로 매번 생성한 임의의 64자리 HEX 토큰을 발급하고 **원문은 성공한 본인 브라우저 응답에만 한 번** 전달. DB에는 SHA-256 해시만 기록. 응답은 `no-store`, `no-referrer`, 제한된 CORS. 브라우저는 서비스 역할 키를 받지 않음.
- 기본 OFF 스위치에서는 발급 요청을 `LV3_NOT_RELEASED`로 거절한다. 서비스에 실제 배포·활성화는 현재 허용되지 않는다.

`js/beagu-lv3-session-v1.js`

- 추후 Lv3 계정 UI에서 쓸 **비활성·미삽입** 헬퍼. `issue` 호출 뒤 동일 토큰으로 `verify`를 추가 확인한 경우에만 `getState().verified=true`; 발급 응답 단독·로컬 HTML 데이터만으로 Lv3 표시하지 않음.
- 메모리에만 임시 토큰 유지, `sessionStorage/localStorage`에 원문 토큰 영구 저장 금지. 로그아웃 즉시 토큰·상태 제거, 서버 `logout` 시도. 이 JS는 현재 공개 웹 및 기존 Lv0–2 페이지에 로드하지 않음.
- 나중에 화면이 표시되더라도 **보호 자료 열람 권한은 서버 API가 재검증해야 한다.**

## 배포 금지 및 이후 단계

1. 4단계의 운영 DB 암호화 백업+독립 복구 검증 및 5단계 실제 Auth 콜백 설정 확인 미완료.
2. **17단계 본인 2026 설문 응답↔고유번호 원본 증명 연결 및 과거 참여자 안전 백필 미완료**. 검증된 응답이 없는 상태에서 새 코드를 배포하면 정상 회원의 접근이 Lv0로 떨어질 수 있음.
3. 18단계 원기기 최초 claim에 대한 과거 코드 소유권 분쟁·복구/이관 정책 미완료.
4. 신규 Auth·Lv3 API와 계정 화면의 실제 합성 E2E 미실행. 실제 서비스에서의 Lv3 권한 발급·관리자 승인·최신 2026 자료 공개 정책·긴급 롤백 검증 미완료.
5. **이번 단계는 '권한 발급이 가능한 서버 코드 및 독립 테스트'를 완성한 것**이며, 실제 사용자에게 Lv3 등급을 부여하거나 데이터 열람·계정 UI를 출시한 것이 아님. 릴리스 스위치 기본 OFF 상태를 변경하지 않는다.

**다음 단계는 20단계**로, 서버 검증 결과를 기존 Lv0/Lv1/Lv2 화면과 정합되게 표시하는 실제 Lv3 계정 상태 UI/혜택 접근 구조를 개발 브랜치에서 다룬다. 모든 개인 권한과 공개 자료는 서버에서 최종 판정해야 한다.
