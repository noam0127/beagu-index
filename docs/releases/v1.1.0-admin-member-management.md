# 배구지수 v1.1.0 — 15단계 관리자 회원관리 검증

**적용 범위:** GitHub `develop/v1.1.0-phase1-20261121` 브랜치의 관리자 회원관리 UI/Edge API/DB 마이그레이션 초안. **현재 운영·시험 웹과 DB에는 배포하지 않았음.**

## 현황 및 기존 구조 점검

현재 관리자 `admin.html`에는 회원관리, 계정 검색·목록·상세, 이메일 확인 상태, Lv2 계정 연결 상태, 기존 문자 수신 동의, 24시간·7일 계정 정지·해제 기능이 이미 구현되어 있었다. 이에 따라 15단계는 **기존 기능을 유지하면서 개인정보 최소 접근과 실제 서버 권한·감사 완전성을 보완**하는 단계다.

운영 DB의 시스템 카탈로그를 읽기 전용 조회하여 `public.beagu_admin_accounts`와 `public.beagu_admin_audit_events`의 RLS 활성화, 서비스 역할 전용 접근권한을 확인했다. 감사 테이블의 기존 outcome 허용값은 `success`, `denied`, `error`이며, 조치 시작 전 `pending` 감사 기록을 남기려면 마이그레이션이 필요하다는 점을 확인했다. 운영 Auth의 실제 이메일, 회원명단, MFA 토큰, 비밀번호, SMS 번호 및 감사 사유 내용을 읽거나 변경하지 않았다.

### 보완 사항

- **최고 관리자(Owner) + MFA 필수:** 기존 `beagu_admin_active_mfa_session` 재검증과 Auth 서버 `getUser()` 검증에 더해 회원관리의 검색·상세·정지/해제를 **모두 최고 관리자에게만** 허용. 프런트에서 비소유자에게 회원관리 링크·패널을 숨기지만 최종 권한은 서버에서 다시 확인.
- **회원 목록·검색:** 이메일/회원 ID 검색과 필터(전체, 이메일 인증/미인증, 정상, 이용 정지). 한 번에 20건씩 페이지 조회. 기존 Auth 목록 조회 한계인 **최대 4,000개 계정 스캔**은 유지하며, 일부만 검색한 경우 UI에서 제한을 명시. 검색 결과에 원본 휴대폰번호나 설문 응답 정보 제공하지 않음.
- **회원 상세:** 계정 생성·인증·최근 로그인·정지 상태·Lv2 연결 여부 및 최소 감사 기록을 표시. 16단계 이후 개인정보 처리·탈퇴 기능을 예고하되 이 단계에서 탈퇴/삭제·Lv3 승급 기능을 임의로 제공하지 않음.
- **문자 동의 안내 정확성:** 기존 `beagu_admin_member_sms_status_v1`는 14단계에서 확인한 사용자 편집 메타데이터 기반 가입 기록까지 동의로 표시할 위험이 있었음. 새 `beagu_admin_member_sms_status_v2`는 비공개 DB에 **별도 번호 수집 동의·SMS 수신 동의·서버 인증 시각·미철회**가 모두 충족된 기록만 동의로 표시. 번호 원문은 UI·API 응답에서 제외.
- **계정 정지·해제 보안:** 관리 권한이 있는 관리자만 일반 회원의 Auth 계정을 24시간/7일 정지하거나 복구 가능. 자기 자신 및 관리자 계정은 이 경로에서 변경 금지.
- **감사 기록 선행:** 기존 구현은 Auth 사용자 정지 이후 감사 기록을 남겨 기록 실패 시 **정지 사실이 기록 없이 남을 수 있었음**. 수정안은 조치 전에 `member_moderation_requested`(`pending`) 이벤트를 남기고, Auth 변경 성공·실패를 별도 이벤트로 기록. 동일 `request_id`의 요청 중복 등록은 **DB 유일 인덱스**로 차단. 감사 기록이 확정되지 않으면 UI가 조치 성공을 확언하지 않으며 재조회하도록 안내.
- **개인정보 노출 최소화:** 사유에서 전화번호·이메일·토큰·링크 형태를 제한. 로그아웃, 관리자 자격 만료 또는 접근 거부 시 회원 이메일·ID·검색어·조치 사유·상세 정보 등 브라우저 DOM을 지움. HTML 직접 주입 없이 `textContent` 사용, 서비스 역할 키 브라우저 미포함.
- **안전한 요청 처리:** POST JSON 본문 3KB 제한, 서버측 UUID·조치 종류·사유 길이 검사, JWT/AAL2·세션 실시간 확인. 공개 JWT 또는 참여코드로 회원 관리 불가.

### 추가·변경 파일

- `admin.html` — 최고 관리자 회원관리 메뉴, 검색 필터, 감사 주의 문구 및 개인정보 최소화 안내
- `js/beagu-admin-members-v1.js` — 서버 필터, 요청 ID, 정지·해제 확인, 유효하지 않은 인증 시 DOM 제거
- `supabase/functions/beagu-admin-members-v1/index.ts` — 소유자 인증, 작은 요청 제한, 감사 선행 및 중복요청 방지, v2 문자 동의 상태 조회
- `supabase/functions/_shared/beagu-member-management-v2.ts` — 순수 입력·상태 필터·감사 데이터 검증 모듈
- `supabase/migrations/20261121233000_beagu_admin_member_management_v2.sql` — `pending` 감사 결과 지원, 요청 ID 유일 인덱스, 서비스 역할만 실행 가능한 검증된 SMS 동의 요약 RPC
- `tests/v1.1.0-admin-member-moderation.test.ts`, `tests/v1.1.0-admin-members-ui.test.mjs`, `tests/admin-member-moderation-fixture.sql`, `tests/admin-member-moderation-verify.sql`, 기존 `tests/admin-members-static.cjs` — Deno/Node/격리 PostgreSQL 보안 및 기능 검증
- `.github/workflows/v1.1.0-admin-member-management.yml` — 자동 회귀 및 격리 DB 마이그레이션 검사

## 테스트 및 출시 차단

CI 결과: [GitHub Actions — 15단계 관리자 회원관리](https://github.com/noam0127/beagu-index/actions/workflows/v1.1.0-admin-member-management.yml). **최종 성공 실행의 결과와 커밋은 진행 기록 문서에서 확인.**

격리 CI는 실제 사용자 정보가 없는 Postgres 16에서 다음을 확인한다.

- 14단계 SMS 안전 마이그레이션 → 15단계 감사 이력/권한 마이그레이션 순서 적용
- `anon`·`authenticated`의 직접 감사 테이블 접근 및 v2 문자 상태 RPC 실행 거부
- 관리 조치 `pending` 이벤트 기록과 동일 요청 ID 재등록 차단
- 사용자 편집 메타데이터 기반 구형 동의를 유효한 수신 동의로 간주하지 않음
- 이메일 인증 후 두 가지 선택 동의를 완료한 계정만 문자 동의 상태 표시, 철회 이후 즉시 비활성
- 최고 관리자/운영자 클라이언트 화면 분리, 검색 필터, 개인정보 입력 차단, 유효하지 않은 관리자 세션의 DOM 정보 삭제
- Deno Edge TypeScript 검사 및 기존 관리자 MFA·포스트잇 작성 권한 회귀 테스트

**실제 운영 변경 보류 사유**

1. 4단계의 운영 DB 암호화 백업·격리 복구 검증 미완료. 운영/시험 DB에 SQL이나 Auth 사용자 변경을 적용하지 않는다.
2. 15단계 새 Edge API는 **14단계 SMS 안전 마이그레이션 및 15단계 DB 마이그레이션 선행 적용**을 전제한다. 순서가 바뀌면 배포를 차단해야 한다.
3. 기존 계정의 Auth 사용자 메타데이터 내 남아 있을 수 있는 과거 전화번호 정리, 관리자 옛 SMS 조회 RPC 비활성화, 실제 Owner MFA 및 감사 성공/실패 E2E는 별도 검증이 필요하다.
4. **Supabase Auth 계정 정지(`ban_duration`)만으로 기존 액세스 토큰·Lv2 참여코드가 즉시 무효화되지는 않는다.** 즉시 전 기능 차단을 보장하려면 서버의 별도 정지 상태 확인·세션 폐기 정책이 필요하다.
5. 개인정보 탈퇴·삭제와 정식 Lv3 계정 권한은 각각 16단계 및 18~20단계에서 처리한다.
