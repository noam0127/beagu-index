### Supabase 보안 권고 사항

- `anon_security_definer_function_executable`: **6개 경고**, 인증 사용자도 동일 6개. 실제 함수 본문을 확인했으나 **익명 악의적 호출·남용·연속 호출을 이용한 우회 실증은 미완료**. 공개 RPC는 진행도(집계값), 검색·조회·성능 기록 등의 용도를 갖기 때문에 보안 검토 없이 EXECUTE 권한을 일괄 회수하면 운영 기능이 깨질 수 있음.
- `extension_in_public`: `pg_net` 1개 경고. 별도 계획하에 검토.
- `auth_leaked_password_protection`: 비밀번호 유출 목록 검사 활성화 권고 1개. Auth 대시보드 설정 검증 필요.
- `rls_enabled_no_policy` 정보성 87개: 비공개 테이블은 공개 정책이 **없는 것이 의도된 제한**일 수 있으므로 전체를 취약점으로 오인하지 말 것.
- 참조: https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable

## 정적 소스 계약

현재 소스에서 확인한 필수 방어:
1. 레벨 API는 서버가 발급한 세션 SHA-256 및 만료를 검사하고, 2026 추천 자격을 재검증하며 승인 자료만 읽도록 제한한다.
2. 포스트잇 API는 조회·쓰기 각각 Lv2 서버 검증, 쓰기 시 Auth 계정·회원 연결·기기 소유 인증을 요구한다.
3. 관리자 회원 API는 서버 `getUser` 검증, 관리자 사용 상태, AAL2 MFA, 활성 MFA 세션을 확인한 다음 액션을 실행한다.
4. 시험 웹 패키징은 운영 Supabase URL이 남으면 실패하도록 설계되어 있다. **단 실제 배포된 시험 웹의 격리는 아직 확인되지 않았다.**
5. 브라우저 JavaScript/HTML의 Supabase secret key/JWT 리터럴 혼입 여부를 정적 검사한다.

**제한:** 문자열·구조 검사는 동적 우회 공격과 사용자 간 데이터 노출을 완전히 증명하지 못하며, 테스트의 통과가 출시 승인을 의미하지 않는다.

- 소유권 조회와 상태 갱신 및 `removed=true` 반환은 전 회차에서 수정한 영향 행 확인 로직으로 처리. 이번에는 **정상 작성부터 본인/타인 삭제까지 한 요청 흐름의 실제 E2E**가 확인됐다(선행 단순 SQL 테스트의 한계를 보완).

**시험 환경 및 정리:**
- 재현 자산: `tests/staging/stage35-real-postit-crud-claim.sql`, `tests/staging/stage35-postit-crud-real-once.ts`, `tests/v1.1.0-stage35-postit-crud-real-once.py`, `.github/workflows/v1.1.0-stage35-postit-crud-real-once.yml`.
- 테스트 서버에는 클라이언트 입력이 없는 1회 실행 함수와 비공개 시험 잠금을 사용. 테스트 후 서비스 역할 접근 코드를 제거한 **HTTP 410 비활성 함수 v2**로 교체하여 실제 배포 소스를 재확인했다. 공개 호출을 위한 `stage35_claim_crud_once()` SQL 함수도 시험 DB에서 DROP했고, 일회성 잠금 행은 재실행 방지 기록으로 유지.
- 시험 DB를 별도 확인: `auth.users` 0, `beagu_postit_member_accounts` 0, `beagu_postit_posts` 0, `beagu_postit_comments` 0, `beagu_postit_reactions` 0, `beagu_level_sessions WHERE identity_campaign='stage35'` 0. 즉, 개인 시험 JWT·가상 게시글이 남지 않았다.
- 위 일회성 HTTP 테스트는 성공 후 비활성화되어 **그대로 재실행할 수 없다**. 재검증 시에는 새 잠금과 격리 데이터 세트, 안전한 종료 절차를 별도로 준비해야 한다.

**남은 필수 조건:** 정식 **Lv3 가입·메일인증·승급** 전체 E2E, 실제 **관리자 AAL2 MFA가 적용된 제재·감사** E2E, 실제 2026 자료의 승인지연·최종 공개 플로우 등. 본 회차는 정식 회원 간 포스트잇 작성/삭제 IDOR 핵심을 실제 HTTP로 통과했지만 **35단계 전체 완료는 아님, 36단계 보류**. 운영 DB·운영 웹·main 미변경.
