# 배구지수 v1.1.0 · Stage 38 실제 Edge 소스/시험 웹 연결 비교

2026-11-22 · GitHub PR #244, 운영·시험 Supabase **배포된 Edge 함수 소스 조회만 수행**. 비밀키·개인정보·실제 설문 응답·운영 DB 행은 확인하거나 변경하지 않았다.

## 핵심 발견: GitHub 베이스는 운영 API이고, 시험 API에는 별도 진전이 있다

**결론:** GitHub의 `index.ts`와 `release-policy.mjs`를 단순히 시험 Supabase에 배포하면, 현재 시험 API v5의 **Lv.3·포스트잇 소유권·추가 정책 코드가 사라질 위험**이 크다. 따라서 PR에서 테스트 코드가 통과해도 이것을 곧 시험 백엔드 정합성으로 인정할 수 없다.

또한 시험 Edge API의 Origin 허용값이 현재 `http://localhost:8000`과 `http://127.0.0.1:8000`만 포함한다. 별도로 발행한 **Vercel HTTPS 프리뷰 도메인**은 현 CORS 허용목록에 없다. 즉 브라우저 E2E를 위해서도 정확한 프리뷰 Origin을 소유자 승인 후 등록해야 한다. `*.vercel.app` 전체 허용이나 운영 도메인을 무조건 추가하는 방식은 안 된다.

## 추가한 재배포 사전 차단 장치

- `scripts/release-manager/stage38-backend-source-gate.mjs`의 `--audit`은 저장소의 현재 모듈이 시험 백엔드의 최소 필수 기능을 보유하는지 검사하고, 정상이라도 **배포 승인/실제 호출 검증이 아님**을 구분한다.
- `--require-stage-parity`는 인증 정책·Lv.3 검증/포스트잇 소유권·시험 도메인 제한을 충족하지 못한 소스에 대해 **종료 코드 3**으로 실패한다. 따라서 실제 Edge 배포를 담당할 **별도의 승인된 CI/스크립트**에 나중에 추가할 수 있는 차단 지점이다. 이 파일은 지금 어떤 Edge Function도 배포하지 않는다.
- `tests/stage38-backend-source-gate.mjs`에서 현재 GitHub 코드가 **NO_GO_STAGING_EDGE_REGRESSION_RISK**여야 한다는 사실, 가짜 기능 보유 코드만 `REVIEW_READY_NOT_DEPLOY_AUTHORIZED`로 분류됨, Lv.3·포스트잇·정책·Origin·추천 자격 재검증 각각 제거 시 거부됨을 검증한다.
- 기존 Vercel 프리뷰 워크플로 템플릿에 **Supabase Edge 함수/DB 직접 배포 명령은 없으며**, Stage38 기능이 있는 시험 API v5를 임의 덮어쓰지 않도록 별도 통합 변경 관리가 필요하다.

## 실제 독립 프리뷰 연결 전 해소 순서

1. **실제 시험 Edge v5 소스와 GitHub 운영 베이스를 3방향으로 비교**, Lv.3·소유권·보안용 공유 모듈의 기능을 보존하면서 38단계 신설 인증만 선택적으로 통합한다. 현재 소스 차이를 자동 병합하거나 운영 파일로 강제 치환하지 않는다.
2. Lv.1의 공식 2026 설문 제출 완료 증빙/소유 확인을 먼저 확립하고, 시험 DB에 승인된 합성 참여코드 원장과 인증 함수/RLS를 구현한다. 방문/고유번호 발급/추천 경유 사실을 설문 완료로 대체하지 않는다.
3. 실제 시험 API의 CORS에는 관리자 검토를 거친 **정확한** 독립 HTTPS 프리뷰 Origin만 추가하고, 프리뷰 요청·사전 요청·비허용 Origin 및 인증 누락 실패 응답까지 브라우저로 검증한다. 실제 서비스의 API Origin과 운영 키를 재사용하지 않는다.
4. 현재 v5의 기존 Lv.2 실적 재검증, Lv.3 소유권 연결, 공개 승인/개인정보 보호 규칙을 보존한 회귀검사를 수행한다. 이후 신설 코드 철회/재로그인 동작을 검증한다.
5. 관리자 승인된 고정 RC를 **별도의 실 시험 프리뷰 URL**에 배포하고 화면·브라우저·API·DB·RLS 전체 E2E를 끝내기 전에는 **38단계 완료/실제 운영 배포를 선언하지 않는다**.

**결론: NO-GO.** 이번 비교는 실제 소스 구조와 프리뷰 연결 위험에 대한 읽기 전용 감사 및 자동 테스트 추가다. 운영 main, 두 Supabase DB/Edge 배포 및 기존 Vercel 시험 웹은 그대로 유지된다.
