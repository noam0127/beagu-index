## 작업함·버전 관리 규칙

- **이번 후보는 `release/v1.1.0-rc.1`의 SHA를 고정**하여 참조한다. 브랜치 포인터 자체가 Git 태그처럼 영구 불변이라는 주장은 하지 않는다. 변조/이동 여부를 CI가 체크한다.
- 후속 소스 수정 시 이 SHA/후보 브랜치를 덮어쓰지 않는다. 다음 후보는 별도 `v1.1.0-rc.2`와 별도 SHA로 만든다.
- 관리자 업데이트 페이지의 `register`는 기존 운영 기반 `main` 최신 SHA를 참조하므로 **이 개발 후보를 운영 배포 큐에 임의 등록하지 않는다**. 본 문서와 JSON 매니페스트, PR이 개발 작업함의 기록이다.
- 38단계 이후에 시험·운영 적용을 재검증한 뒤 관리자의 직접 승인으로만 배포한다. RC 등록이 시험 웹/운영 웹 변경을 의미하지 않는다.

**37단계 완료 기준:** 원본 SHA로 후보 분기 생성, 후보 변경·시험·미해결 조건 등록, PR #195 연계, 후보 고정·패키징 검증. 정식 출시/본 웹 업데이트는 별개.
