# 배구지수 v1.1.0 — 운영 배포 CI 증빙 정책 (NO-GO 설계)

> 2026-11-23. **초안 PR #255에만 존재하는 미배포 코드**. 운영 웹, 운영 Supabase, `main`에는 적용되지 않았다.

## 이번 변경으로 서버가 직접 확인하는 것

1. 요청자는 실제 Supabase Auth 소유자(Owner)이며 **활성 AAL2 MFA 세션**이어야 한다. 브라우저의 `confirmed_tested: true`는 배포 의사 표시만 의미하며 시험 통과 증빙이 아니다.
2. 운영 배포 후보는 **실제로 배포된 시험 버전의 SHA 및 버전**과 정확히 일치해야 한다. 시험 성공 이력의 `stage_apply`, `to_sha`, `version`, `deployed_at`은 서버 DB에서 읽는다. 후보 SHA는 GitHub `main` HEAD와 동일해야 한다.
3. **동일 SHA**를 대상으로, **시험 배포 이후** GitHub Actions에서 별도 실행한 아래 세 워크플로를 서버가 직접 조회한다. 각 워크플로는 전체 SUCCESS, 명시된 필수 작업 및 **모든 작업·시험 단계 성공**이어야 한다.

| 필수 워크플로 파일 (운영 저장소) | 반드시 성공해야 하는 작업 이름 | 목적 |
|---|---|---|
| `v1.1.0-acceptance-e2e.yml` | `release-acceptance-e2e` | 실가입·메일 링크·추천→Lv3·관리자와 릴리스 |
| `v1.1.0-acceptance-security-privacy.yml` | `release-security-privacy` | 인증·RLS·실자료의 독립 개인정보 승인 |
| `v1.1.0-acceptance-desktop-mobile.yml` | `release-desktop-mobile` | 실제 PC·모바일·회귀·성능 검증 |

   GitHub API에서 식별 가능한 `workflow_dispatch` 실행이어야 하고 `head_sha`, `head_branch=main`, 저장소 식별자, 워크플로 파일 경로, 실행 완료, 최신 결과, 독립 실행 ID를 모두 대조한다. 데이터 조회 실패, 미존재, 스킵, 실패, 중단, 누락은 **전부 거부**한다. 증빙 유효기간은 시험 배포 이후 **7일**이다.
4. **운영 적용 버튼뿐 아니라** 별도 OIDC 서명으로 동작하는 GitHub 배포 워커가 큐를 가져가기 **전** 동일한 CI 증빙을 다시 확인한다. 이미 실행 중이었던 운영 배포 작업의 완료 요청도 방어적으로 확인한다.
5. 자동 최초 배포(`bootstrap`)와 자동 공개자료 갱신(`data_refresh`)은 승인된 시험 증빙이 없는 한 자동 작업을 생성하지 못하도록 차단한다. **긴급 운영 롤백**은 현재 owner MFA + 명시적 사용자 승인 경로를 따로 유지한다.

## 지금은 왜 운영 배포 NO-GO인가

- 위 세 개의 이름을 가진, 독립적인 **실서비스 수용 자동시험 워크플로는 아직 운영 main에서 통과한 상태가 아니다**. 검사할 수 있는 결과가 없으면 이 코드는 자동으로 거부하도록 설계했다.
- QA 별도 저장소에서 이미 통과한 **가상 사용자·가상 추천 자료 기반** 실서버 시험, 원격 QA Pages A→B→A와 실제 관리자 MFA 버튼 시험은 중요한 검증 기록이지만, **운영 main 후보 SHA의 수용 증빙을 대신하지 않는다**.
- 사용자 수신 이메일의 실제 확인 링크 클릭·추천→Lv3→2026 자료 조회를 한 번에 통과한 브라우저 E2E, 실제 2026 응답의 소집단/차분/재식별 **독립 전문가 승인**, 운영과 동일한 PC·모바일 회귀 검증은 별도로 필요하다.
- GitHub Actions 워크플로가 수정 가능한 경우, 성공 기록만으로 사람의 개인정보 검토까지 대체해서는 안 된다. 실제 개인정보 검토의 **독립적인 서명·기록·취소 절차**는 아직 완성되지 않았으므로, 이 CI 게이트를 전체 출시 승인이라고 해석하지 않는다.

## 변경·검증 위치

- `supabase/functions/beagu-release-manager-v1/release-ci-proof.mjs`: GitHub Actions 검증의 **실서버 로직**.
- `supabase/functions/beagu-release-manager-v1/index.ts`: 관리자 운영 요청·서명된 워커 모두에서 검사.
- `js/beagu-admin-updates-v1.js`: 배포 차단 이유 한국어 안내.
- `tests/v1.1.0-release-ci-proof.mjs`: 성공/실패/위조·기한·완료 여부 단위시험.
- `tests/v1.1.0-release-ci-integration.mjs`: 버튼 및 서명 워커의 우회 경로 정적 검사.
- `.github/workflows/v1.1.0-release-ci-gate.yml`: **GitHub 배포·Supabase 쓰기 권한 없음**, 개발 브랜치만 시험.

## 실제 배포 전 필수 인계

현 시스템의 공개자료 자동갱신·최초 배포 운영 정책을 이 안전 차단과 충돌 없이 재설계해야 한다. 세 워크플로와 개인정보 승인 정책을 구현·독립 검증한 이후, 브라우저·서명 워커·정확한 SHA 증거·복구를 같은 운영과 분리된 환경에서 최종 통과시켜야 한다. **아무 검증도 완료되지 않았는데 이 게이트를 해제해선 안 된다.**
