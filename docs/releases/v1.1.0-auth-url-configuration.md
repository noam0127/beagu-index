## 구현된 코드 및 상태

- `js/beagu-auth-return-v1.js`: 현재 브라우저 URL이 공식 `https://baeguindex.com`인지 확인하고, `/_preview/` 경로면 반드시 같은 시험 경로로 복귀합니다. 미등록 페이지·알 수 없는 호스트는 오류로 차단합니다.
- `challenge.html` / `js/challenge-member-auth-v1.js`: 회원가입의 `emailRedirectTo`를 정확한 챌린지 주소로 지정.
- `postit.html` / `js/postit-account-v1.js`: 기존 Google 로그인 `redirectTo`를 고정하고, 이메일 회원가입에는 누락됐던 `emailRedirectTo`를 명시.
- `admin-enroll.html` / `js/beagu-admin-enroll-v1.js`: 관리자 등록 이메일 인증도 정확한 경로로 복귀하도록 고정.
- `docs/releases/v1.1.0-auth-redirect-matrix.json`: 서버별 설정값과 **아직 대시보드 적용이 검증되지 않았다는 상태**를 기록.
- 해당 변경은 `develop/v1.1.0-phase1-20261121` 브랜치에만 존재. `main` 운영 웹, 시험 웹 공개 배포, Supabase 프로젝트 설정은 변경하지 않았습니다.

## 자동 검증

GitHub Actions [#44903747202](https://github.com/noam0127/beagu-index/actions/runs/44903747202) **성공**. Node.js 테스트 4건 통과:
1. 운영/시험 Site URL 및 명시적 Redirect URL의 매핑 일치
2. 미등록 페이지, 공격자 호스트, HTTP/localhost 접근 거부
3. 인증 화면 세 곳의 스크립트 로딩 순서 및 함수 사용
4. 대시보드 미확인 상태와 서로 다른 프로젝트 구분 보존

**이 검증은 소스/오프라인 테스트만 실행한 것**으로, 실제 인증 이메일 발송·링크 클릭·Supabase 원격 설정의 유효성은 확인하지 못했습니다.

## 완료를 위한 추가 검증

1. 실제 백업·복구 증빙이 확보되었음을 먼저 확인합니다. 현재 4단계에서 발견한 리스크가 해소되지 않은 경우 **실제 Auth URL 설정 변경은 보류**합니다.
2. 안전조건 충족 후 두 대시보드에서 정확한 Site URL과 Redirect URLs를 설정·저장하고, 등록 결과를 검증합니다.
3. 이메일 템플릿의 링크가 `{{ .RedirectTo }}`를 의도대로 사용하고 있는지 확인합니다. 사용자 정의 템플릿이 `{{ .SiteURL }}`에만 고정돼 있다면 요청한 복귀 주소가 무시될 수 있습니다.
4. 6단계의 이메일 인증 콜백 구현 및 실제 인증 E2E에서 링크 복귀 URL, Supabase 프로젝트, 사용자 세션을 검사합니다. `/_preview/`는 운영과 호스트가 같아 별도의 격리된 브라우저 프로필이 필수입니다.
5. 검증되지 않은 경우 진행 기록에서 **5단계 미완료**를 유지합니다.
