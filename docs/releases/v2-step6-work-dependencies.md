# 배구지수 통합 업데이트 시스템 v2.0 — 6단계: PR 상태·의존 관계 분석

2026-11-22 · PR #201(5단계)의 **개발 브랜치 위에 쌓은 후속 PR** · 운영 배포/DB 변경 없음

## 문제

여러 ChatGPT 채팅방이 각각 웹을 수정할 때, 서로 다른 PR을 한꺼번에 결합하면
선행 PR이 누락되거나, 중단된 PR에 의존하거나, 순환 의존성이 생길 수 있다.
**GitHub에서 병합되었다는 사실은 통합 테스트나 운영 배포 완료 증빙이 아니다.**

## 6단계에서 실제 구현한 것

1. PR 본문의 명시적 `Depends on: #193`, `Blocked-by: #199`, `선행 PR: #201` 등을 분석한다.
   - 본문 일반적인 `#NNN` 언급, 단순 PR 링크는 의존성으로 취급하지 않는다.
   - 원본 PR 본문은 API에 내보내지 않고 번호 목록만 정규화한다.
2. PR의 `base.ref`가 조회된 다른 PR의 `head.ref`와 **유일하게 일치**하면
   해당 작업을 선행 PR로 추론한다. 중복되거나 모르는 브랜치는 임의 선택하지 않는다.
3. 번호별 의존성 그래프에서 **누락·미병합 종료·다른 브랜치 병합·진행 중·순환 의존성**을 구분한다.
4. `main`에 병합된 선행 PR이라도 통합 후보가 실제로 해당 커밋을 포함하는지
   별도로 확인해야 하므로 `requires_ancestry_review`로 표시한다.
5. PR 조회가 300개 상한에 걸리거나 API 페이지가 실패한 경우, 그래프를 완전히 검증한 것으로 표시하지 않는다.
6. 관리자 개발 작업함에는 차단·점검 사유, 선행 PR 번호, 증빙 미확인 안내를 표시한다.

## 허용되지 않는 상태 혼동

| GitHub의 사실 | 관리자 화면에서 정확히 표시할 것 | 이 사실만으로 주장하면 안 되는 상태 |
|---|---|---|
| Draft PR | 개발 중 | 코드 통합 완료 |
| Open PR | 병합 대기 | 기능 검증 완료 |
| `main` 병합됨 | GitHub 병합 완료 | 버전 생성 완료 |
| 버전 카탈로그에 SHA 존재 | 버전 생성됨 | 시험 웹 적용 완료 |
| 시험 배포 이력 있음 | 시험 배포 실행 이력 있음 | 브라우저 E2E 검증 완료 |
| 운영 배포 기록 있음 | 운영 배포 성공 기록 있음 | 회귀 오류 없음 |

`ready_for_validation`은 **통합 테스트를 수행할 후보**를 의미한다.
코드 병합 또는 웹 공개를 자동 승인하는 신호가 아니다.
각 PR의 `release_inclusion`, `integration_tests`, `staging_verification`,
`production_verification`은 **별도 검증이 있기 전까지 무조건 미확인**으로 남긴다.

## 단계별 연계

- **7단계:** 수정 파일·DB 마이그레이션·Edge Function·테스트 증빙 자동 분석
- **8단계:** 같은 파일·경로를 수정한 작업을 사전 충돌 위험으로 알림
- **9단계:** 선택 PR에 선행 PR을 포함하고 별도의 통합 브랜치 생성
- **10단계:** Git 3-way merge 충돌 해결, 수정 내역 및 의존성 검증
- **11단계:** 단위·통합·보안·E2E 테스트 통과 후 통합 승인
- **12단계:** 통합 검증을 통과한 SHA를 불변 버전으로 저장
- **후속 배포 단계:** 시험 환경 검증, 진행 상태 막대기(대기→실행→결과),
  복구 대상 SHA가 없는 최초 롤백 요청 금지, 별도 최종 운영 승인

현재 6단계는 정규화된 PR 메타데이터만으로 상태를 판단하므로 코드에 실제
함수 호출 의존성이 있는지, DB 변경이 겹치는지는 알 수 없다. 그 부분은
7~11단계에서 코드·스키마·런타임 검증으로 추가한다.
