6. 보호된 승인 URL의 실응답·전체 파일 무결성·브라우저 스토리지 분리·인증·RLS E2E까지 완료한 이후에만 38단계 종료를 검토한다.

현재 4개 존재하는 시험 RPC는 모두 `anon`, `authenticated`에 직접적인 호출 권한이 없다(일반 권한 평가 기준). **이는 반드시 결함이라는 뜻이 아니다.** 해당 API가 서비스 역할 또는 제한된 서버 연결로 RPC를 호출한다면 클라이언트의 직접 호출을 열어서는 안 된다.

**새 재현 도구:** `tests/stage38-staging-rpc-parity.sql`은 위 10개 RPC에 대해 **이름 누락·인자 불일치·반환형 불일치·DEFINER/INVOKER 차이**를 구분하는 메타데이터 SELECT 쿼리이며, `stage_private.fake_schools`가 존재하는 시험 DB에서만 결과를 반환하도록 추가 확인한다. `tests/stage38-staging-rpc-parity.mjs`는 SQL이 쓰기·권한 변경 문장을 포함하지 않고, 기대한 함수 계약이 모두 명시돼 있는지 CI에서 정적으로 확인한다.

**안전 원칙:** 시험용 함수가 INVOKER인 것은 합성 QA용으로 의도된 안전 설계일 수 있다. 운영의 `SECURITY DEFINER` 구현을 무분별하게 복사하거나 `GRANT EXECUTE`를 자동 추가하지 않는다. 서버 경로·사용자 인증·권한 검증 방식과 시험 데이터만으로 대체 가능한지 검토한 뒤 **별도 관리자 승인을 받아야** 한다. 함수 이름·인자·반환형 일치는 런타임 동작이나 관리자 MFA 보안을 보증하지 않는다.

## 서버 전용 RPC 실제 실행 권한 메타데이터 검증
