# 배구지수 v1.1.0 — 12단계 계정 오류 안내 UX

## 적용 범위

개발 브랜치 `develop/v1.1.0-phase1-20261121`의 **챌린지 / 포스트잇 로그인·회원가입** 화면에만 적용. 운영·시험 웹 배포, Supabase DB/Auth 설정, 사용자 계정은 수정하지 않음.

### 오류 안내 원칙

- **서버의 원문 `error.message`/이메일/토큰/내부 오류를 UI에 절대로 반영하지 않는다.** API가 반환한 `error.code` 및 HTTP `status`를 알려진 범주로 분류하고 개발자가 직접 작성한 고정된 한국어 문구만 `textContent`로 보여준다.
- 로그인 실패 시 없는 계정·틀린 비밀번호·인증되지 않은 이메일·정지 계정을 사용자에게 구체적으로 구분해 드러내지 않는다. 로그인/인증 메일/비밀번호 재설정을 일괄 안내한다.
- 회원가입 실패 시 `email_exists` / `user_already_exists` / `signup_disabled` 등을 서로 구분하지 않고 동일한 도움 문구를 보여준다.
- 정해진 위험도 없는 오류는 안전한 일반 오류 안내로 대체한다. 단, **429 요청 제한**, **네트워크 장애**, **서버 일시 장애**, **새 비밀번호 보안 기준 미충족**은 독립적으로 설명할 수 있다.
- 로컬 폼 검증 오류(이메일 형식, 신규 비밀번호 10자, 선택한 문자 안내 휴대폰번호)는 제출 전에 구체적으로 안내한다. 기존 계정 로그인 비밀번호에 신규 가입자 길이 정책을 적용하지 않는다.
- `aria-live=polite` 상태 영역을 그대로 이용하며, 서버 요청 중 제출/모드 전환 버튼을 비활성화하고 폼에 `aria-busy=true`를 표시해 중복 제출을 방지한다. 완료/실패 후 버튼을 원상복구한다.
- 메시지/아이콘/색상은 **인증 권한 자체가 아니며**, 작성 권한은 여전히 기존 Auth `getUser()`, Lv2 `beagu-level-api`, Post-it `writer_status` 서버 응답만으로 결정한다.
- 관리자 MFA 화면이나 서버 권한 정책을 변경하지 않는다.

## 새 공통 오류 메시지 모듈

`js/beagu-auth-errors-v1.js`의 `window.BeaguAuthErrorUI`:

| 표시 범주 | 판단 근거 | 사용자 안내 |
| --- | --- | --- |
| 로그인 입력 누락 | 브라우저의 직접 입력 상태 | 이메일과 기존 비밀번호 입력 요청 |
| 회원가입 입력 누락 | 직접 입력 상태 | 이메일과 10자 이상 새 비밀번호 요청 |
| 선택 문자 번호 오류 | 동의 체크 + 번호 형식 오류 | 010으로 시작하는 11자리 번호 안내 |
| 인증/참여코드 재검증 거부 | 기존 자체 `LEVEL_REQUIRED` | Lv2 참여코드 재인증 |
| 로그인 실패 | Supabase 기타 로그인 오류 | 이메일/비밀번호/인증 메일/비밀번호 재설정 통합 안내 |
| 회원가입 실패 | 중복·사용자 정보·설정 오류 등 | 계정 존재 여부를 공개하지 않는 일반 안내 |
| 요청 과다 | HTTP 429 또는 공식 `over_*_rate_limit` 코드 | 몇 분 후 다시 시도 |
| 네트워크 문제 | Supabase `AuthRetryableFetchError`, `TypeError` | 네트워크 확인 후 재시도 |
| 새 비밀번호 약함 | 회원가입의 `weak_password` | 더 안전한 10자 이상 새 비밀번호 안내 |
| 서버 일시 장애 | HTTP 5xx | 잠시 후 다시 시도 |
| Google OAuth 실패 | 제공자 관련 오류 | 이메일 로그인 등 대체 방법 안내 |
