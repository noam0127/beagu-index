# 배구지수 v1.1.0 — 20단계: Lv3 정식 계정 상태 UI 및 혜택 경로

**2026-11-22. 완료 범위: 개발 브랜치의 UI·상태 연결, Lv3 인증 헬퍼 재사용 및 자동 테스트. 실제 Lv3 회원 인증·권한 발급·2026 비공개 자료 공개·운영/시험 DB 및 웹 배포는 모두 미실행.**

## 화면 구성

- `challenge.html`, `postit.html`: 기존 Lv2 참여코드 인증/정식 계정 로그인·원기기 연결 UI를 유지하면서, **서버가 `lv3LinkReady:true`를 확인한 경우에만** `Lv3 정식 회원 인증` 패널과 인증 요청 버튼 노출. 발급만 된 고유번호·미확인 계정·다른 사람에게서 받은 코드·미연결 계정은 패널 비노출.
- `js/beagu-lv3-account-ui-v1.js`: 버튼을 눌러야 19단계 별도 Lv3 `issue`/추가 `verify` API를 호출. **두 번의 서버 확인에 성공한 경우에만** 일시적인 Lv3 상태 표시. 운영 릴리스 스위치가 OFF이거나 계정/2026 설문/추천 품질이 무효면 인증 완료를 표시하지 않음. 문구는 승인 대기/접근 불가 이유를 추측하거나 실제 배포됐다고 말하지 않음.
- `js/beagu-lv3-session-v1.js`: 이미 19단계에서 구현한 **30분 제한, 메모리 보관, Auth+Lv2 이중 증명** 헬퍼 그대로 사용. Lv3 원문 토큰을 DOM, 로컬/세션 저장소, URL, 배지 이벤트에 노출하지 않음. 사전 서버 발급 응답만으로 실제 혜택을 열지 않음.
- `js/challenge-member-auth-v1.js`, `js/postit-account-v1.js`: 로그인 확인 및 Lv2 원기기 계정 링크의 서버 응답에 따라 패널 보임/숨김. 로그아웃·Lv2 취소·연결 미인증·세션 상태 오류 시 즉시 Lv3 표시와 메모리 토큰 제거. 포스트잇 작성·검색은 기존 Lv2 서버 권한검사를 재사용하며, **Lv3를 이유로 기존 허용 범위를 확장하지 않음**.
- `js/beagu-level-state-v1.js`: 페이지 헤더의 기존 참여코드 인증 `data-level` 값은 **Lv0~Lv2 그대로** 둠. 별도 서버에서 인증된 회원에게만 **장식용 `data-member-level=3` 및 `Lv.3` 텍스트** 표시. 사용자에게 Lv3 등급이 해제되거나 추천 자격이 취소되면 텍스트와 접근성 설명은 즉시 **Lv.2로 복귀**. 상단 Lv3 배지는 보호된 자료 접근 권한으로 사용하지 않음.
- `levels.html`, `js/beagu-level-guide-v1.js`, `styles/beagu-level-guide-v1.css`: 레벨별 4개 카드를 반응형으로 정리. Lv3 **정식 회원 단계의 인증 조건과 예정 혜택**을 설명. 현재 Lv2 이상 사용자도 Lv3를 별도 확인해야 하며, 브라우저를 이동하면 임시 Lv3 토큰은 메모리에서 사라져 재인증해야 함.
- `styles/beagu-lv3-account-ui-v1.css`: 모바일 버튼/안내문, 키보드 초점, 인증 상태에 따른 명확한 시각 구분을 통일.

## 2026 레벨별 혜택 정책 표시 — 실제 공개는 아직 비활성

| 등급 | 기획 중인 2026 검증 자료 공개 정책 |
|---|---|
| Lv0 | 기본 공개 자료 및 기존 공개 정책 유지 |
| Lv1 | 학교 상세 결과, 공개 심사 완료된 2026 자료의 24시간 후 열람 예정 |
| Lv2 | 유효 추천 1건, 공시지가 정렬, 승인된 2026 자료의 6시간 후 열람 예정 |
| Lv3 | 서버 검증된 Auth 계정, 2026 최신 학교 기본정보 및 공개 심사 완료 자료의 즉시 열람 예정 |

**이 단계에서 실제 데이터 엔드포인트는 열지 않았다.** Lv3 패널의 인증 표시와 2026 학교 자료 접근 권한은 서로 구별된다. 2026 공개 승인·학교별 개인정보·소표본 위험 심사 및 서버 권한 검증을 거친 엔드포인트에서만 자료 열람을 허용해야 한다. 실제 차등 공개 시간 정책과 공개 엔드포인트 구현은 후속 단계.

## 보안 설계

- 브라우저 이벤트 `beagu:lv3-session-verification`, `data-member-level`, `dataset` 등의 값은 사용자가 임의로 변경할 수 있는 **표시 상태에 불과**하며, 서버의 SQL `beagu_lv3_verify_session_v1`와 무관하다. 서버 보호 API는 향후 **매 요청** 19단계 토큰 및 현재 Lv2/계정 관계와 데이터 공개 심사를 재확인해야 한다.
- Auth `SIGNED_OUT`·`USER_DELETED`·`TOKEN_REFRESHED`, 재검증 실패, 연결 상태 변경 시 기존 Lv3 뷰와 토큰을 제거한다. 인터넷 연결 오류·릴리스 OFF는 성공으로 처리하지 않음.
- Lv3가 활성 상태여도 `beaguLevelState.dataset.level==='2'`를 유지해 0~2 참여코드 API·포스트잇 작성 인가 등 기존 로직이 깨지지 않음.
- 어느 화면도 회원가입 직후 Lv3를 부여하거나 SMS 수신동의를 자동 선택하지 않음. Lv2 유효 추천과 Auth 원기기 소유권 검증을 우회하는 가입·출시 버튼 없음.
- 4단계 암호화 운영 DB 백업·격리 복구 및 5단계 원격 Auth URL 확인, 17단계 Google Forms 원본 응답↔고유번호 연결, 18단계 기기 소유권 분쟁/복구 검증의 차단 조건 유지. **실제 DB/Auth 설정이나 사용자 계정은 조작하지 않았다.**
