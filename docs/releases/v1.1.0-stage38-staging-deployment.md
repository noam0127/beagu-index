## 이번 38단계에서 실제 구현·검증

- 개발 브랜치 서버 `beagu-release-manager-v1`에 새 **`register_stage_candidate`** 액션 추가. 기존 최고 관리자 + 실제 AAL2 검증을 그대로 적용하고, GitHub 공개 RC ref가 지정한 40자리 SHA와 정확히 일치하는지 검사한 후 **시험 전용 초안**으로만 등록. 임의 버전·잘못된 SHA·변조된 브랜치는 실패.
- `stage_apply`가 관리자 등록 RC를 최신 `main` 제안으로 **무단 대체하지 않도록** 수정. `prod_apply`는 RC 버전의 운영 승격을 직접 차단.
- 관리자 업데이트 화면에 **고정 후보 등록**, **배포 진행 상태 가로막대**, 적용 완료/실패/대기 표시, 서버가 확인한 최근 작업 상태를 추가. **시간을 근거로 30%, 50%를 만들어 표시하지 않고**, 대기는 0, 실제 실행 중은 진도 미정, 서버 `deployed` 상태에서만 100%.
- [38단계 시험 후보 사전검사 Actions #44972879069](https://github.com/noam0127/beagu-index/actions/runs/44972879069) 성공: 실제 RC SHA와 GitHub ref 일치, 서버·클라이언트 단계별 권한 판정, 불변 SHA 패키징, 프리뷰의 시험 Supabase 격리 확인.
- **실제 설치하지 않고** RC 정적 사이트를 만들어 GitHub Actions 임시 다운로드 아티팩트 `beagu-v1.1.0-rc.1-offline-preview`로 업로드. 산출물 ID `14734447202`; 배포 확인이 아닌 **오프라인 검사 가능 패키지**.
- 운영 release manager/DB와 `main` 미수정. 개발 PR #195에는 배포 경로 개선 코드만 추가.

## 확인된 필수 차단 조건

1. 현재 배포 서버는 `main` 커밋만 자동 등록한다. 새 RC 경로를 개발 브랜치에서 구현했지만 **실제 운영 배포 서버에는 적용하지 않았다**. 운영 서버 수정은 별도 관리자 승인·검토가 필요하다.
2. 관리자 **실제 AAL2 세션**이 없으므로 RC 후보 등록·시험 배포 버튼 요청을 대리 실행할 수 없다. 계정·MFA 우회 금지.
3. 현재 GitHub Pages `/_preview/`는 37단계 RC SHA와 다르다. HTTP 200이나 오프라인 아티팩트 성공을 **시험 배포 완료로 보고할 수 없다**.
4. 향후 **업데이트 관리자 패널**에서 RC SHA 등록·시험 적용 후 `public.beagu_site_release_jobs_v1`과 `state_v1.staging_sha`, `history_v1` 확인, 실제 HTTP·백엔드 격리 검증까지 마쳐야 **38단계종료**로 인정.
5. 36단계의 관리자 AAL2 성공 경로·실제 2026 승인자료 심사·실제 이메일 확인·수동 운영 승인 4개 NO-GO는 그대로 유지. RC 운영 배포 금지.

### 38단계 추가 검증 — RC 생산 배포 우회 차단 및 후보 SHA 재검증 (2026-11-22 KST)

- 고위험 결함 수정: `prod_apply`가 **화면에 표시된 RC 버전 문자열만** 확인하면, 예를 들어 `stage_rollback`이 버전을 `이전 시험 버전`으로 표시할 때 동일 RC 코드가 운영에 승격될 가능성이 있었다. 개발 브랜치 서버는 이제 **고정 RC 소스 SHA 자체**를 차단하고, 이전 `staging` 배포 기록에서 같은 SHA로 발행된 RC 버전이 있는지도 조회한다. 이력 조회에 오류가 나면 운영 배포를 허용하지 않는다.
- `stage_apply`는 실제 후보 SHA가 원격 GitHub `release/v1.1.0-rc.1`과 맞는지 **등록 시뿐 아니라 실행 시에도 재확인**한다. RC 후보를 시험에 이미 적용한 경우 `main` 최신 커밋으로 후보를 조용히 바꾸지 않는다.
- 관리자 UI는 코드 SHA 또는 RC 버전이 확인되면 `실제 웹 적용` 버튼을 비활성화하고 이유를 표시한다. 서버 차단이 최종 권한이고, 프런트엔드 잠금은 안내 보조 기능이다.
- **검증:** [GitHub Actions 38단계 보안/패키징 회귀 #44973305529](https://github.com/noam0127/beagu-index/actions/runs/44973305529) **PASS**. 순수 함수로 원본 RC SHA/버전 변경/롤백 레이블/깃 브랜치 변조/승격 차단을 테스트했으며, RC 사이트는 오프라인 검증 패키지로만 생성했다.
- 운영 Supabase를 읽기 전용으로 재확인: 실제 `staging_sha=41fa2fe4c68cf533f9183806ac3e16f31f662612`, `production_sha=5950755c8174788d7bb1fa879be73a15f25d9ae2`; 등록된 RC SHA `5c95aadad971901a8222f83c52e93bf901a3aeb7`와 **여전히 불일치**. 운영 DB 수정 및 본 웹/시험 웹 배포를 수행하지 않음.

**38단계 진행 중.** 관리자 AAL2 승인을 통한 실제 RC 시험 배포는 여전히 필요하며, 검증 코드가 통과했다는 이유로 단계 종료를 선언하지 않는다.


### 38단계 재검증 — 서버 SHA와 다른 배포에 100% 완료 표시 방지 (2026-11-22)

- 배포 기록의 최근 작업이 `deployed`여도 **현재 운영·시험 웹의 실제 서버 보관 SHA와 다르면** 진행률 100% 또는 '적용 완료'를 표시하지 않도록 수정했다. 배포 이후 롤백, 변경, 상태 조회 누락일 때 `superseded` 상태로 알려준다.
- 대기 중에는 0%, 배포 중에는 퍼센트 미확정, 현재 SHA와 성공 이력이 일치할 때만 100%를 표시한다. 시간 경과를 근거로 수치를 임의 생성하지 않는다.
- [단위/패키징 GitHub Actions #44973530836](https://github.com/noam0127/beagu-index/actions/runs/44973530836) **성공**: 구버전 완료 작업, 없는 현재 SHA, 운영·시험 교차 대상, 현재 SHA 일치, RC 검증·패키징 전체 통과.
- 이 코드는 **개발 브랜치만** 수정한 것이며 실제 관리자 화면·운영 API에는 아직 적용하지 않았다. 운영 및 시험 배포는 실행하지 않음.
