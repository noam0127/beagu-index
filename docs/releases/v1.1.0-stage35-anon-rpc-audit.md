# v1.1.0 — 35단계: 운영 공개 고권한 RPC 감사 및 성능 기록 요청 제한 실험

2026-11-22 KST · 개발 브랜치 `develop/v1.1.0-lv3` · **운영 DB/운영 웹 무변경**

## 1. 실제 운영 DB 읽기 전용 감사

- `SECURITY DEFINER` 함수 53개 중 `anon` 또는 `authenticated`에 직접 EXECUTE 권한이 있는 함수 6개 확인.
- 공개 함수는 `beagu_get_challenge_progress`, `beagu_log_school_search`, `beagu_perf_record_v1`, `beagu_record_school_interest`, `beagu_record_school_view`, `beagu_school_view_counts`.
- 이 6개는 챌린지 순번, 학교 검색/조회수/관심도, 성능 측정용이다. 공개가 의도된 것일 수 있으며 **일괄 REVOKE 금지**. 공개 입력·개인정보·비정상 요청·서비스 남용 위험을 함수별로 별도 심사해야 한다.
- `beagu_perf_record_v1`의 원래 호출자별 제한은 `(p_visitor,page,operation)`마다 20초. 하지만 `p_visitor`를 호출자가 임의의 UUIDv4로 바꿀 수 있으므로 다른 UUID를 제출할 때 제한이 우회될 수 있다. 이는 *측정량의 신뢰성/운영 DB 쓰기 부하 위험*이며 개인 응답 정보가 실제 유출됐다는 증거가 아니다.
- 최근 7일 실제 성능 샘플 총 **1,174건**, 샘플이 있었던 **31개 시간**의 시간당 평균 **37.9건**, 최대 **202건**(집계값만 확인, 방문자/학교 식별정보 조회 없음). 시험 상한 **시간당 10,000건**은 검증용 기준이며 운영 적용 전에 성장 목표에 맞춘 재산정 필요.
- 운영 Security Advisor: `anon_security_definer_function_executable`/ `authenticated_security_definer_function_executable` 각 6건 경고(동일 함수), `extension_in_public` `pg_net` 1건, `auth_leaked_password_protection` 경고 1건, `rls_enabled_no_policy` 정보성 87건. 이들은 원인·필요성별로 검토하고, 경고만 보고 정책·확장을 변경하지 않았다.

## 2. 개발 및 시험 DB에 구현한 보호

- `tests/staging/stage35-perf-global-budget-dependencies.sql`: 격리 시험 프로젝트에 사용자 기록/성능 샘플/관리자 계정의 구조상 최소 더미 테이블. RLS 및 직접 SQL 조회 차단.
- `tests/staging/stage35-perf-global-budget-prototype.sql`: `stage_private.fake_schools` 마커가 없으면 **실행 중단**되는 시험 전용 SQL.
  - `beagu_private.beagu_perf_global_budget_v1`의 시간 버킷별 원자적 `INSERT ... ON CONFLICT DO UPDATE ... WHERE used < 10000`로 전체 쓰기 예산을 공유.
  - `beagu_private.beagu_consume_perf_global_budget_v1`: 비공개 `SECURITY INVOKER` 함수로 위 예산 확인.
  - 공개 `beagu_perf_record_v1`의 입력 검증·관리자 차단·방문자별 20초 제한·샘플 기록을 유지하고 **방문자별 테이블에 쓰기 전에 전역 예산을 확인**한다. 방문자 UUID 교체로 새 쓰기 행을 무한히 만들 수 있던 경로의 부하에 상한을 준다.
  - 비공개 테이블 세 개는 RLS 활성, `anon`·`authenticated` SELECT 없음. 공개 RPC만 의도적으로 익명 호출 허용.
- 이 SQL은 **운영 적용용 마이그레이션이 아님**. 운영으로 이행하려면 검증된 버전 관리 마이그레이션, 성능·사용량 예산, 오래된 버킷 정리(보존기간), 장애 시 fail-closed 정책, 관리 승인 단계가 별도 필요.

- [Actions #44968297128](https://github.com/noam0127/beagu-index/actions/runs/44968297128): 다시 빈 가상 데이터·예산 9996에서 시작 → **16개 UUID를 동시 요청**, 정확히 4회만 허용하고 12회 거부. 경쟁 상태에서 전역 예산이 초과되지 않음. 성공.
- 두 HTTP 검증은 **시험 공개용 publishable 키**만 사용하고 운영 API, 응답자 기록 및 service_role 비밀키에 접근하지 않았다.
- `tests/staging/stage35-perf-global-budget-cleanup.sql`을 실제 시험 DB에서 실행해 **샘플 0건, UUID별 제한 0건, 전역 예산 버킷 0건**을 확인. 시험용 스키마와 함수는 재현 가능하도록 남겨두었다.
- 이 보호는 익명 텔레메트리의 **DB 기록량 상한**만 보장한다. 익명 호출이 인증 사용자임을 증명하지 못하며, 봇 트래픽·거짓 이벤트·전체 HTTP 요청률을 없애는 방어는 아니다. 한 공격자가 시간별 예산을 소모하면 정상 텔레메트리가 일시 누락될 수 있음.

## 4. 잔여 통과 조건

- 35단계 최종 종료 요건: 시험 Auth 회원 2명을 이용한 실제 교차 계정 IDOR/포스트잇 소유권·정지 계정 E2E, 관리자 MFA/감사 상태, Lv3 가입 및 2026 정식 승인 데이터 공개 권한 종합 E2E.
- 이 중 회원·Lv3 기능은 17~20·33~34단계의 선행 구현이 필요하다. **35단계 진행 중**이며 **36단계는 보류**한다.
- 시험용 새 테이블·함수를 **운영 DB/운영 웹에 배포하지 않았다**. 운영 `main`은 그대로다.
