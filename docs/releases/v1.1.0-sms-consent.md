# 배구지수 v1.1.0 — 13단계 선택적 휴대폰번호 및 SMS 안내 동의

## 상태

**개발 브랜치 코드·오프라인 CI 완료 / 운영·시험 웹 미배포 / 실제 DB 저장·철회 검증은 14단계 이후.**

휴대폰번호는 회원가입을 위해 **필수로 요구하지 않는다**. 이용자가 문자 소식을 원하면 별개인 두 항목을 **각각 직접 선택**해야 한다.

1. **휴대폰번호 수집·이용 동의(선택, 기본 미선택)** — 설문 소식·서비스 안내·광고성 문자 발송 목적의 번호 취급.
2. **SMS/LMS 문자 수신 동의(선택, 기본 미선택)** — 설문·서비스 정보와 광고성 정보의 문자 수신.

동의하지 않아도 계정 생성과 일반 서비스 이용에 불이익이 없다는 사실을 분명히 표시한다.

## UI에서 제공하는 정보

- 수집 항목: 휴대폰번호
- 이용 목적: 배구지수 설문·서비스 소식 및 광고성 문자 발송
- 보유 기간(적용할 정책): 문자 수신 동의 철회 또는 회원탈퇴 시까지. 별도 법정 보존 의무가 있는 경우 실제 적용 법령에 따라 확인해야 하며 최종 운영 개인정보 처리방침과 일치하도록 검토해야 한다.
- 거부할 권리: 선택 항목은 모두 미동의 가능, 미동의로 인한 회원가입/서비스 이용 불이익 없음
- 철회 방법: 로그인한 계정의 ‘문자 수신 동의 철회’ 버튼. 14단계에서 비공개 저장소의 삭제와 수신 차단 실제 작동 여부까지 확인.
- 연락처 형식: 양쪽 동의 체크 시에만 입력 활성화, `010`으로 시작하는 11자리 숫자. 번호 확인·법적 발송 요건 검증 전에는 문자 발송을 허용하지 않는다.

## 구현

- `challenge.html`과 `postit.html`의 각 가입 폼에 별도 체크박스, 비활성 번호 입력란, 명확한 안내문, `aria-labelledby`/설명 연결을 추가. `checked` 기본 속성은 사용하지 않는다.
- `js/beagu-sms-consent-v1.js`: 동의 체크 변경 시 두 항목 모두 승인된 경우에만 전화번호 입력 활성화. 한쪽이 해제되면 브라우저의 입력 번호를 삭제하고 다시 비활성화.
- 선택 결과는 **두 항목 모두 미체크** 시 `beagu_sms_opt_in=false`, `beagu_phone_collection_opt_in=false`, `beagu_sms_phone=null`로 직렬화하여 **휴대폰번호 문자열을 전송하지 않는다**.
- **둘 중 하나만 동의한 경우**에는 수신 동의나 번호 수집을 임의로 추정하지 않고, 두 항목 모두 동의하거나 모두 해제해 달라는 안내를 제공한다.
- **둘 다 동의한 경우**에만 번호를 정규화해 `beagu_sms_phone`에 넣고, `beagu_sms_opt_in=true`, `beagu_phone_collection_opt_in=true`를 함께 제출한다.
- `js/beagu-account-mode-v1.js`: 로그인/가입 화면 전환 시 비밀번호·연락처·두 동의 체크값 모두 삭제.
- `js/challenge-member-auth-v1.js`, `js/postit-account-v1.js`: 실제 `signUp()`에는 `smsPrivacy.payload().consent`만 전달. 기존 사용자 로그인에는 번호/동의값 전송 없음. 수신 동의 철회 시 Auth 사용자 메타데이터의 두 플래그를 `false`로 바꾸고 전화번호를 `null`로 업데이트하는 기존 방법도 함께 정리.
- `js/beagu-auth-errors-v1.js`: 부분 동의 안내 메시지 추가.
- `styles/challenge-member-auth-v1.css`, `styles/postit-account-v1.css`: 별도 동의 구분·비활성화 표시·키보드 초점 개선.

## 보안·개인정보 한계

이 단계의 Auth `user_metadata` 값은 **사용자가 변경할 수 있는 메타데이터**이므로 마케팅 발송 승인/회원 등급/RLS의 권위 있는 근거로 사용하지 않는다. 이 개발 브랜치 자체로 발송 권한, 철회 기록, 가입 시 동의 일시·버전, 비공개 저장소의 번호 암호화, 외부 발송업체 동기화 또는 삭제가 검증되었다고 볼 수 없다. **14단계에서 별도 비공개 영속 저장소의 허용된 서버 기록·RLS·감사·철회 동작과 실서비스 데이터 흐름을 검증할 때까지 실제 홍보문자 발송을 금지한다.**

사전에 확인된 위험: 운영 DB 암호화 백업과 격리 복원이 검증되지 않았고(4단계), Supabase Auth의 원격 리디렉션 허용목록을 확인하지 못했다(5단계). 따라서 이 단계에서 DB/Auth 서버 설정과 사용자 데이터를 수정하거나 운영·시험 웹에 배포하지 않았다.
