# 배구지수 v1.1.0 — 16단계 개인정보 열람·문자 수신 철회·탈퇴 검토 요청

> **개발 브랜치 코드 및 격리 테스트만 완료. 운영·시험 DB, 실제 회원 Auth 계정, 개인정보 처리방침, 운영 웹에는 배포/변경하지 않음.**

## 목표와 처리 범위

회원 본인이 **Lv2 챌린지 인증 여부와 무관하게** 이메일 인증을 거친 정식 Auth 계정으로 로그인하여 다음을 수행할 수 있게 만든다.

1. **내 계정정보 요약 열람:** 내 이메일, 가입 시각, 최근 로그인 시각, 서버 인증된 문자 수신 동의 상태, 개인정보 열람·탈퇴 요청의 최신 상태를 확인.
2. **자세한 개인정보 열람 요청 접수:** 자동 응답으로 모든 개인 기록을 즉시 노출하지 않는다. 추가 자료 목록과 수집 출처를 관리자 검토 후 제공해야 한다.
3. **문자 수신 동의 철회:** 기존 14단계 `beagu-member-sms-api-v2`를 재사용해 비공개 저장소에서 연락처 삭제, 수신 동의 무효화, 레거시 Auth 메타데이터 정리 성공 여부를 확인.
4. **탈퇴 검토 요청 접수·취소:** 가입한 이메일 주소 및 정확한 확인 문구 `계정 탈퇴 요청`을 직접 입력하고 확인창에 동의하면 요청을 **접수**한다. 회원 계정과 포스트잇·추천·설문·검토 기록은 **즉시 삭제되지 않는다**. 처리 시작 전까지 요청을 철회할 수 있다.
5. **Owner의 접수함:** 최고 관리자+MFA가 활성화된 `admin.html` 회원관리 안에서 접수 대기·처리 중인 개인정보 열람/탈퇴 요청(요청 ID·계정 UUID·상태·시각)을 확인할 수 있다. **전화번호·이메일·원문 사유/인증정보는 접수함에 표시하지 않는다.** 관리자 검토함 자체는 계정 삭제나 요청 완료 기능이 아니다.

## 서버 권한 및 보안 설계

- Deno Edge `supabase/functions/beagu-member-privacy-api-v1/index.ts`: JWT를 Supabase Auth의 `auth.getUser(jwt)`에서 검증. 이메일 인증·비익명 계정만 허용. 검증된 JWT의 `session_id`가 `auth.sessions`에서 유효한 세션인지 **별도 서비스 전용 RPC**로 재확인.
- API POST만 허용하고 미등록 origin 거부. 1KB 이하 JSON만 받으며 응답에 `Cache-Control: private, no-store` 등 개인정보 캐시 방지 헤더 적용. `status`, `request_access`, `request_deletion`, `cancel_access`, `cancel_deletion`만 제공.
- 개인정보 목록은 **로그인한 본인에게만** 반환. 브라우저가 보낸 `user_id`는 무시. 서버는 `auth.getUser`로 확인한 `user.id`만 비공개 RPC에 전달.
- `supabase/migrations/20261121234500_beagu_member_privacy_requests_v1.sql`: `beagu_private.member_privacy_requests_v1` 비공개 접수 테이블. 요청 종류·상태·시각·UUID만 저장하며 이메일, 휴대폰번호, 비밀번호, 토큰, 원문 요청 본문, IP 등을 저장하지 않음. `anon/authenticated` CRUD 차단·RLS 활성화. `beagu_member_privacy_*_v1` / `beagu_member_live_session_v1` / `beagu_admin_privacy_queue_v1` RPC는 **service_role EXECUTE 전용**.
- 같은 종류의 미완료 요청은 **부분 유니크 인덱스**로 한 계정당 1건만 허용. 일일 요청 생성 최대 5회 제한. 미처리 요청만 취소 가능; 이미 `processing`이면 단순 취소로 삭제를 중단했다고 안내하지 않음.
- 관리자 계정은 본인 계정 탈퇴 셀프서비스 요청을 허용하지 않음. 별도 관리권한 승계/감사 절차가 필요하므로 `ADMIN_REVIEW_REQUIRED`로 처리.
- Owner의 개인정보 요청 접수 목록은 기존 `beagu-admin-members-v1`의 `getUser(jwt)`·MFA AAL2·실제 세션·`owner` 재검증 후 제공. Owner 자격 만료/로그아웃 시 회원·요청 목록의 개인정보가 브라우저 DOM에서 삭제됨.
- **영구 삭제 기능을 이 단계에서 실행/제공하지 않음.** `auth.admin.deleteUser`, SQL `DELETE auth.users`를 이 단계의 고객 요청 API에 추가하지 않았다.

## 운영 DB 외래키 위험 발견 (읽기 전용 카탈로그 조회)

운영 Supabase `snvzwrexuqavnfvzgxqj`의 PostgreSQL 카탈로그에서 `auth.users`를 참조하는 다음 관계를 확인. **실제 사용자 행 또는 계정 식별자·개인정보는 조회하지 않음.**

- `public.beagu_postit_member_accounts.auth_user_id`: `ON DELETE CASCADE`. 단, 포스트잇의 `author_uid`와 작성 게시글·댓글·반응·신고가 따로 유지되는지 검토해야 하므로 **연결 행만 지워서 완전 탈퇴 처리되었다고 간주할 수 없음**.
- `beagu_private.member_sms_subscriptions_v1.user_id` 및 14단계 감사 이벤트: `CASCADE`. 문자 수신 철회는 계정 삭제와 분리해 즉시 처리 가능하도록 별도 엔드포인트 유지.
- `public.survey_submissions.user_id`: `ON DELETE SET NULL`. 기록의 조사·통계적 의미를 유지하면서 연결만 제거하도록 되어 있으나 탈퇴/삭제 시 법적·통계적 보존 근거 확인 필요.
- `beagu_private.beagu_2026_basis_review_events.actor_user_id`, `beagu_private.beagu_2026_publication_basis_review.reviewer_user_id`, `beagu_private.challenge_referral_quality_audit.actor_user_id`, `beagu_private.challenge_referral_quality_reviews.reviewer_user_id`: **기본 `NO ACTION` FK**. 관련 행이 있으면 Auth 계정의 일괄 삭제가 실패할 수 있음. 감사 증거의 보존과 개인 식별자 최소화를 균형 있게 처리하는 별도 익명화/법적 보존 검토가 필요.
- `beagu_private.beagu_admin_owner_approvals_v1.activated_user`, `beagu_private.beagu_admin_signup_invites_v1.redeemed_by`: `SET NULL`; `public.beagu_admin_accounts.user_id`는 `CASCADE`.
- `public.beagu_admin_audit_events.actor_user_id` 등 외래키 밖에 남는 식별자는 **별도 연관 데이터 및 보존 정책 감사**가 필요하다.

이는 자동 `deleteUser()`를 즉시 호출하지 않은 주요 이유다.

## 사용자 화면

- `account-privacy.html` — **Lv2 참여코드가 없어도 접근할 수 있는** 개인정보 센터. 기존 Auth 이메일·비밀번호 로그인 및 이미 로그인된 세션을 지원. 기존 비밀번호에 신규 가입 길이 정책 적용 안 함. SMS 철회 API 버튼 별도 제공. 가입 상태에 따라 전체 메뉴 노출/숨김.
- `js/beagu-account-privacy-page-v1.js` — 본인 Auth 재검증, 로그인·로그아웃, 문자 철회 성공 확인. 미인증 시 개인정보 화면 미표시.
- `js/beagu-account-privacy-v1.js` — 공용 본인정보 열람·추가 자료 요청·탈퇴 검토 요청 및 취소 컴포넌트. 계정 로그아웃/인증 해제 즉시 표시된 이메일·요청 확인 입력·요약 정보를 초기화. 서버 원문 오류·토큰·연락처를 화면에 삽입하지 않음.
- `challenge.html`, `postit.html` — 인증 완료된 계정의 개인정보 패널 및 독립 센터 링크. `index.html` 하단에도 별도 센터 링크.
- `styles/beagu-account-privacy-v1.css` — 반응형 폼·키보드 접근성·읽기 쉬운 신청/철회 버튼, 숨김 정보는 실제 `hidden`으로 관리.

## 실제 배포·탈퇴 완료의 필수 후속 조건

1. 4단계 **암호화 백업 및 독립 복구 검증**, 5단계 Auth Redirect URL 설정과 시험/운영 분리 조건을 우선 충족.
2. 시험 DB에 14·15·16단계의 SQL을 순서대로 적용한 뒤, Edge API와 프런트엔드를 **합성 계정으로 실제 브라우저·네트워크 E2E** 검증.
3. 관리자 검토 절차로 Auth-FK 제약과 포스트잇·설문·추천·관리자 감사·첨부파일/스토리지 등 **전체 연결자료 목록**을 확인하고, 정정/익명화/보존 의무를 정의한 후에만 탈퇴/삭제 실행 구현을 승인.
4. **탈퇴 요청 접수와 실제 회원 탈퇴 완료는 다른 상태**다. 실제 삭제·보존 예외·처리 완료 통지는 이 단계에서 자동화하지 않았으며, 완료된 것처럼 표시하지 않는다.
5. 개인정보 추가 열람 요청은 현재 **접수 기능**이다. 모든 원자료의 자동 내보내기와 처리 완료/이의 신청 이력은 별도 개인정보보호 정책·관리자 검토/이행 기능을 요구한다.
6. 독립 개인정보 센터의 **Google OAuth 신규 로그인 콜백**은 별도의 Auth redirect URL 등록 전까지 제공하지 않는다. 기존 Google 계정 세션은 접근할 수 있으나 이메일·비밀번호가 없는 계정은 추가 로그인 지원이 필요하다.

공식 참고: [Supabase Auth 사용자 관리](https://supabase.com/docs/guides/auth/managing-user-data), [Auth 관리자 사용자 삭제](https://supabase.com/docs/reference/javascript/auth-admin-deleteuser), [Supabase Auth 세션](https://supabase.com/docs/guides/auth/sessions).

**상태 결론:** 코드·격리 테스트까지 완료할 수 있지만, 운영 계정의 실제 탈퇴/삭제를 끝냈다고 주장할 수 없다. 실제 삭제 기능은 독립 복구·보존 정책·관련 데이터 정리가 검증된 이후에만 별도 승인 후 제공한다.
