# 챌린지 별도 보존 · 인디스쿨 공유 UX 조사 (2026-11-19)

상태: **Draft PR #49 개발 브랜치의 챌린지 코드만 분리 / 운영 미배포 / 추천 공유 UI는 설계 단계**.

## 1. 두 기능의 목적을 명확히 분리

### A. 2026 배구지수 챌린지 (기존 보존)

- 고정 경로: **/challenge.html** (삭제·이름 변경·레벨업 이동 경로 전환 금지).
- **참여 순번**, **인증서 PNG 저장**, 챌린지 링크 복사가 목적.
- 기존 3종 고유번호와 기존 DB 기록 보존; 이는 챌린지 과거 참여 식별용이지 **로그인 수단/레벨업 수단이 아님**.
- 챌린지 화면은 기존 Lv1 인증 게이트를 유지한다. 외부에 링크를 공유한 방문자도 원래 접근 정책을 따른다. **공개 무인증 전환은 별도 보안 검토 없이 하지 않음**.
- 기존 이미지 영역 #certificate만 캡처한다. 고유번호, 개인 인증 상태, 계정 ID, 초대 링크를 캡처 이미지에 넣지 않는다.
- Draft 브랜치에서는 옛 방문자 고유번호 기반 추천 패널 #challengeReferralPanel과 해당 enroll JS를 제거했고, 독립 #challengeSharePanel/#copyChallengeUrl/#challengeShareFeedback을 추가했다. 챌린지 URL 복사는 인증서 영역 밖에서만 가능.
- 기존 API의 타인 visitor UUID로 고유번호 원문 조회 가능한 운영 취약점은 **아직 미해결**. 챌린지 링크 공유와 별개로 인증 코드 발급 API 보안 패치 필요.

### B. 계정 레벨업용 개인 추천 링크 (신규 계정 체계)

- 전용 위치: 공통 **레벨업하기** 패널, 또는 로그인 계정의 '내 전용 링크' 영역.
- 로그인된 **레벨1** 계정만 발급·조회(이메일 확인 등 추가 조건은 최신 v3 문서).
- URL 예시 형태만: **https://baeguindex.com/survey.html?ref=<opaque-token>** (실제 토큰은 서버 발급 전까지 없음).
- 기존 공식 Google Form URL, 추가 2개 문항 및 Apps Script payload는 유지. 서버는 응답 이벤트와 개인 Auth 계정의 추천 토큰을 대조. 클릭만으로 승급되지 않음.
- 제3자 설문 응답이 1회 유효하게 집계되면 해당 계정이 레벨2로 자동 승급. 클라이언트가 레벨을 임의 지정하지 못하도록 서버 원장 기준.
- 추천 링크에는 이메일, 고유번호, visitor UUID, Auth JWT, 개인 정보 등을 삽입하지 않는다.
- 챌린지 인증 이미지에 추천 링크를 숨겨 넣거나 챌린지 화면 방문을 강제하지 않는다.

## 2. 인디스쿨 공유 정책 확인 — 공식 자료

**2026-04-28 갱신된 공식 게시판 목적 안내**:
https://support.indischool.com/hc/ko/articles/51686994593433

- 쫑알쫑알(라운지 포함)은 SNS, 사이트, 모임 등 홍보가 제한되며, 라운지에서 홍보성 추천 링크를 게시하면 제재 위험이 있다.
- **커뮤니티 > 함께해요**는 개인 SNS·이벤트 등 홍보를 허용하되 **게시글 맨 앞 [광고] 표시**, **주 1개 이하** 등 규정을 요구한다.
- 자료실은 독립 외부 사이트로 유입을 유도하는 홍보 게시물을 금지한다.

**2026-05-06 갱신된 홍보 세부 규칙**:
https://support.indischool.com/hc/ko/articles/51687471584281

- 경제적 보상 관계가 있으면 명확히 알리고, [광고] 또는 [홍보]를 본문 상단에 표시한다. 
- **레벨2 승급이라는 개인 이용 권한 혜택이 있다는 사실도 투명하게 안내**한다.
- 게시판 운영정책의 최신 내용이 바뀔 수 있으므로 실제 공유 시 사전 재확인 권장.

**2025-11-14 운영정책 개정본**:
https://policy.indischool.com/community-guidelines

- 도배/과도한 홍보를 제재할 수 있음. 인디스쿨에 **자동 업로드**, **매크로**, **대량 댓글/메시지 전송** 기능은 개발하지 않는다.

따라서 추천 링크를 '인디라운지에 바로 게시하기' 버튼으로 연결하는 것은 **부적절하다**. 사용자에게 **[인디스쿨 공유 글 복사]** 옵션과 게시판 가이드를 제공하되, 최종 글 작성/게시 판단은 사용자가 한다. 공식 인디스쿨 게시판 글쓰기 API, 직접 게시 URL, 텍스트 자동 링크화 여부는 확인되지 않았으므로 **그 기능을 지원한다고 단정하거나 URL을 추측하지 않는다**.

## 3. UX 제안 (2차 개발 시 구현)

Lv1 + 로그인 계정의 '레벨업하기'에서:

1. **내 전용 링크** (서버 발급한 불투명 토큰을 보이는 URL로)
2. **링크 복사** — URL만 클립보드에 복사
3. **공유하기** — 브라우저가 지원하면 navigator.share({title,text,url})로 OS 공유창을 열기. 지원하지 않으면 링크 복사. **인디스쿨 자동 게시가 아님**.
4. **인디스쿨용 글 복사** — 아래의 정직한 홍보용 짧은 문구 + 실제 링크를 클립보드에 복사. 팝오버/하단 안내로 '**함께해요 게시판**, [광고] 표기, 일주일에 글 1개' 명시.
5. **진행률 0/1 → 1/1**, 재조회 후 ‘레벨2로 승급되었습니다!’ 알림. 다른 기기에서 로그인하면 최신 레벨 재조회.

예시 텍스트(브라우저에 실제 링크가 발급된 때만):

> [광고] 2026 배구지수 설문에 참여하실 선생님을 찾습니다.
>
> 전보·학교 선택에 도움이 되는 학교별 조사 자료를 만드는 프로젝트입니다.
> 아래 링크로 기존 공식 설문에 참여하실 수 있습니다.
> 이 링크를 통해 유효한 설문 응답이 접수되면 저에게 배구지수 레벨2 이용 권한이 주어집니다.
> 응답 여부는 자유롭게 결정해 주세요.
>
> {나의 실제 전용 링크}

- 보상 설명을 빼거나 '추천인에게 아무 이익 없음' 같은 거짓 안내 금지.
- 개별 커뮤니티 게시판의 실제 활성 정책·홍보 범위를 사용자가 재확인하도록 안내.
- 예시 설문 URL을 "배포 중 작동하는" 링크로 표현하지 않음: Google Form 사전 입력 entry ID 및 서버 실적 적립이 완전히 연결된 후 공개.

## 4. 테스트와 책임 범위

- [ ] 인디스쿨용 글 복사에 [광고], 혜택 공개, 실제 토큰 삽입

## 5. 다음 구현 순서

- 계정 시스템 및 공통 '레벨업하기' 플로우 먼저 개발 (v3 참조).
- 기존 사용자 ID 기반 추천 RPC/Edge는 새 **Auth account ID 기반 추천 원장**으로 교체 (옛 코드 로그인 폐기).
- 신규 레벨업 패널의 공유 기능(링크복사/공유하기/인디스쿨용 글 복사) 구현.
- 인디스쿨 실제 에디터의 URL 자동 링크 처리·글자 수 제한 등은 **플랫폼에서 수동 점검 후** 조정.
- 챌린지 화면은 별도 독립 소셜 인증서로 계속 유지하고, 기존 UUID IDOR 문제는 별도 보안 작업으로 처리.
