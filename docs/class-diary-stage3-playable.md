## 이야기의 중심 흐름
1. 월요일: 복합기 앞에서 시작된 불분명한 업무분장과 새 동료.
2. 화요일: 아무도 말하지 않은 동의와 학년 규칙을 다시 협의할 가능성.
3. 수요일: 급식 줄서기의 이유를 묻는 아이들과 학생자치 의사결정.
4. 목요일: 학생과 보호자 사이의 의견 차이, 함께 대응할 교직원.
5. 금요일: 퇴근 후 모임을 선택하거나 거절할 수 있는 문화.
6. 토요일: 의무 출근이 아닌 개인의 시간, 동료와의 자율적 교류.
7. 일요일: 일주일을 수첩에 기록하고 다음 주에 지킬 약속.

## 주인공·호감도·결말
- 주인공 프로필: 나이 20~75세, 성별(여성/남성/밝히지 않음), MBTI 16유형.
- 성인 동료는 여성인 지윤, 남성인 현우, 또는 우정 중심의 익명 동학년 교사 중 선택.
- 나이·성별·MBTI는 캐릭터와 독백을 조금 바꾸지만 점수에서 차별적 불이익을 주지 않는다.
- 점수 4종: 동료 호감도, 신뢰, 학생의 자리(학생 참여·자치), 피로도. 각 0~100.
- 엔딩 5종: 다정한/나란한/단단한/조심스러운/서툰 학급일지. 호감도 외에 신뢰와 학생의 자리도 결과를 결정한다.
- 모든 인물은 성인 허구 인물이며 연애 관계를 강제하지 않는다. 학생의 갈등이나 괴로움을 연애 보상으로 사용하지 않는다.

## 실데이터 연결과 개인정보 경계
- 학교 선택은 기존 1단계 미리보기에서 진행한다. 게임 페이지는 `schoolId`만 URL로 받고, 서버의 `class-diary-world-v1`에서 유효한 Lv2 세션을 재검증한 후 세계를 생성한다.
- 학교의 과거 공개 연도와 공식자료를 확인해야 시작 가능. 세션이 없거나 만료·레벨 미달이면 게임을 열지 않는다.
- 별도 `class-diary-story-signals-v1` API의 검증된 과거 문항 신호만 문학적 사건의 소재로 받는다. 문항 서버 장애 시에는 비공개 자료를 대체 출력하지 않고 일반 허구 장면으로만 진행한다.
- **4단계 방침 변경:** 주인공 프로필·선택·진행·완료 기록은 기기와 서버에 일절 저장하지 않는다. 저장 동의·이어하기·완료 목록도 제거했다. 페이지를 새로고침하거나 벗어나면 현재 플레이는 사라진다.
- 이전 버전에서 브라우저에 남은 게임 로컬 기록은 플레이 페이지 진입 시 삭제하며, 이후에는 localStorage에 게임 데이터를 기록하지 않는다. 기존 Level2 인증 세션은 게임 데이터와 별개로 유지한다.
- 실제 2027년 학교에서 특정 교직원이 발언하거나 특정 사건이 발생했다는 사실을 주장하지 않는다.

## 테스트 및 한계
- Node 자동 테스트는 2,187개 가능한 진행 경로의 정상 종료 및 엔딩 5가지가 실제로 도달 가능한지 확인한다.
- GitHub Actions Class diary world validation에서 엔진·문항 매핑·HTML 인터페이스 정적검사를 함께 실행한다.
- 레벨2 실제 계정으로 웹브라우저를 통한 전 과정 E2E 테스트는 아직 수행하지 못했다. 웹에서 서버와의 통신 성공 여부는 로그인 상태에서 추가 검증해야 한다.
- 외부 이미지, 음향, 캐릭터 스프라이트, 실시간 전역 리더보드, 서버 계정별 이어하기, 학교별 엔딩 랭킹, 다회차 스토리 이벤트는 아직 미구현.
- GitHub Pages 작업이 성공하더라도 CDN 반영과 실제 사용자 세션의 동작은 별개로 확인해야 한다.

## 후속: 4단계
- 인물별 대사와 갈등의 선택별 후속 영향 확대(4단계 첫 구현: class-diary-director-v1.js).
- 기존 레벨2 계정 인증 방식의 변경 사항을 통합 테스트한다. 계정별 진행 저장, 서버 점수 기록 및 전역 순위는 사용자 방침에 따라 개발하지 않는다.
- 학교 데이터 사용률 확대 시 문항별 개별 공개승인과 관련 원자료 검증 우선.
- 시각적 배경·입체적 캐릭터·전환 연출·시각장애 접근성을 함께 개선.
