# v1.11.0 나의 계정 — Lv.2 이중 미션 출시 계약

2026-11-24 사용자 확정: 공통 참여코드 20230904 유지. Lv.1 회원가입 선택. Lv.2 신규 승급은 유효 추천 1건 이상 + 익명 계정 생성 및 인증된 계정 세션. Lv.3 개발 제외. 기존 Google Forms 안내는 변경하지 않는다.

## 1. 권한과 계정 상태 분리
- Lv.0: 로그인 불필요.
- Lv.1: 기존 공통 참여코드 검증 경로를 유지한다. 계정이 없는 참여자도 기존 Lv.1 자료·챌린지를 이용한다. 최초 참여 기기에서 기존 고유번호를 유지하여 비밀번호 4자 이상, 확인란 일치, 일회용 복구코드 회원증으로 선택 가입할 수 있다.
- Lv.2: 신규 회원은 서버가 인정한 유효 추천 1건 이상 및 현재 유효한 익명 계정 인증이 동시에 필요하다. 추천 이벤트 수, 기기 자체 표시, URL 방문, 계정 ID만으로는 승급하지 않는다.
- 미션 순서는 무관하다. 가입 먼저 / 추천 먼저 / 기존 Lv.2 전환을 모두 지원한다. 기존 개인 번호 및 추천 실적, 참여 순번, 작성자 권한은 보존한다.
- 공통코드는 로그인 아이디가 아니다. 개인 고유번호만 로그인 아이디로 사용한다. 공통코드는 개인 계정 생성·변경·복구 또는 커뮤니티 작성 권한을 단독으로 부여하지 않는다. 공통코드만으로 설문 개별 참여가 입증되지는 않는다는 기존 한계를 명시한다.
- 기존 개인 코드의 Lv.2 열람은 기존 달성자의 전환을 위해 보존한다. 운영 적용 직전에 서버에서 이미 유효 추천을 달성한 기존 방문자를 스냅샷으로 확정하고, 신규 달성자는 계정 세션 없이는 Lv.2를 받을 수 없도록 한다. 기존 정적 Lv.2 코드도 별도 검토·전환 대상. 기존 달성자의 개인 고유번호에 연결된 Lv.2 일반 열람 권한은 전환 기한 없이 유지한다. 포스트잇은 열람과 작성 모두 익명 계정 인증을 요구한다. 기존 달성자는 재추천 없이 가입한다. 운영 데이터 수집/스냅샷 실행 및 만료 정책은 이번 코드 개발로 승인된 것이 아니다.
- 기존 회원에게 재설문/재추천을 요구하지 않는다. 원래 기기 증명이 없는 경우 신원 보안 검증을 우회하거나 계정을 임의로 이전하지 않는다.

## 2. 구현 순서 및 출시 차단 조건
A. 서버 정책: 계정 세션 및 유효 추천 AND 판정. 기존 개인 코드 예외 스냅샷 및 공유코드 세션 만료 정책. 공통코드 신규 세션 Lv.1 유지. 기존의 referral-link Edge 직접 세션 승급 및 level-api 개인코드 Lv.2 발급을 모두 수정한다. Post-it, 검색/학교 상세/비교/게임 등 모든 보호 경로와 DB RPC의 권한 확인을 일치시킨다. 신규 예외는 발급하지 않는다.
B. 세션: 계정 먼저 가입한 뒤 추천 성공 시 서버에서 같은 계정의 세션 권한을 안전하게 갱신한다. 추천 철회/비활성화/암호 변경/복구 시 기존 세션 폐기·권한 하향을 검증한다. 기존 코드 세션을 계정 세션으로 위조하거나 다른 방문자의 계정으로 연결할 수 없어야 한다.
C. 공통 UI: Lv.0·Lv.1의 기본 참여코드 인증 진입점을 유지하고 로그인/나의 계정 버튼은 별도로 둔다. 개인 고유번호+비밀번호 로그인, 챌린지 안 간편 가입, 기존 번호 유지, 회원증 저장/자동 로그인. 레벨 표시는 서버 결과만 반영한다.
D. 챌린지 UI: MISSION 01 유효 추천 0/1, MISSION 02 익명 계정 생성/로그인. 순서 무관. 두 미션 완료일 때에만 신규 Lv.2 달성 표시와 전용 기능 활성화. 기존 전환 예외는 '기존 Lv.2 달성 · 혜택 유지'로 구분. 기존 인증 이미지·참여 순번·추천 링크 유지, 공개 이미지에 고유번호·복구코드 금지.
E. 테스트: 공통코드 only, 개인코드 only, 추천 only, 계정 only, 추천→계정, 계정→추천, 추천 철회, 비밀번호 오류·복구·타인 기기·토큰 재사용, 기존 개인 Lv.2 권한의 전환 기한 이후 유지 및 공유코드 세션 만료, 기존 계정과 추천/게시물 보존, PC·모바일, 실제 격리 Supabase, 백업 복원. 전체 CI 최신 SHA 성공 및 서버 적용/롤백 절차 검토 후에만 출시 후보를 확정한다.
F. 관리자 업데이트 센터 등록 준비. 코드·DB·Edge 변경은 별개로 승인 및 적용되어야 하며 관리자 정적 웹 배포만으로 출시할 수 없다.
