## 원본 완료 기준과 구현 범위

**원본:** ‘학교 선택 → 악기 선택 → 연주’만 전면에 남기고 개발자용 정보·장황한 설명을 감춘다. 작은 화면 학교 검색을 다듬고 악기를 클릭하면 즉시 4/4/3/5레인과 터치 패드가 바뀌도록 한다. 학교·악기·게임 진입과 전환, 모바일 레이아웃 스모크 PASS를 기준으로 한다.

이 단계는 기존 리듬게임의 점수·판정·오디오·차트 구조를 유지하면서 **실제 사용자 경로를 한 페이지의 3개 화면/단계**로 개선한다. 단일 페이지에 세 섹션을 순서대로 배치하여 스크롤·포커스 이동으로 ‘화면’처럼 사용한다. 다른 섹션을 DOM에서 제거하거나 완전히 숨기지 않기 때문에 화면 이동 후에도 키보드·스크린리더가 이전 단계로 되돌아갈 수 있다. 별도의 URL이 있는 3개 페이지나 완전한 독립 페이지를 만든 것은 아니다.

### 적용 코드

- **3단계 상단 내비게이션:** `#stepNav`의 ‘1 학교 / 2 악기 / 3 연주’ 버튼을 sticky로 고정하고 `aria-current=step`으로 현재 단계를 알린다. `#stepStatus`는 `aria-live=polite`로 단계 이름을 읽어준다. 현재 단계 테두리는 다른 단계와 구분한다.
- **학교 선택:** 학교 선택 전에는 2·3단계 진입을 차단한다. 선택 후 `goToStep("instrument")`이 두 번째 화면으로 자동 스크롤·포커스 이동한다. `schoolSearch`에 검색 접근성 이름·대상 컨트롤 정보·모바일 검색 키보드 힌트를 추가하고, 320px에서도 검색창과 결과 버튼이 가로 화면을 넘지 않도록 보완한다. 기존 **학교 ID 기반** 검색·공개 집계 난이도 검증 원칙을 건드리지 않는다.
- **악기 선택:** 일렉기타 4레인 D/F/J/K, 드럼 4레인 D/F/J/K, 베이스 3레인 F/Space/J, 키보드 5레인 A/S/D/J/K의 원본 계약을 유지한다. 악기를 누르면 기존 `renderPads()`로 레인·키 레이블·터치 패드·효과 레이어를 즉시 갱신하고 `goToStep("play")`로 연주 화면으로 이동한다.
- **연주:** 연주 중에는 앞 화면으로 내비게이션하지 못하게 하여 소리 시간축과 판정 상태가 끊기지 않도록 한다. `■ 중단` 이후 이전 단계 선택이 다시 가능하다. 연주 버튼, 24px 노트, 키·터치 점수, 효과 줄이기, 볼륨·음소거, 판정 오프셋 등의 기능은 유지한다.
- **문구 정리:** 상단을 학교 고르기·악기 고르기·연주로 줄이고, 창작곡의 실학교 교가 오인 가능성을 줄이는 ‘창작 연습곡’ 문구와 실제 학교 교가가 아직 연결되지 않았다는 안내를 유지한다. 앱 버전 또는 내부 구조 설명은 주요 행동보다 아래로 내린다.
- **개발 QA:** 테스트용 `loadGeneratedTrial()`이 기존 창작 연습곡을 비공개 검수 상태로 열었을 때도 연주 화면으로 자동 이동한다. 사용자가 실제 학교의 교가 이용 허락을 받은 것처럼 표시하지 않는다.
