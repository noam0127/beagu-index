# 『난감한 스쿨밴드』 012/030 — 오디오 중단·음소거·모바일 권한 처리

검증일: 2026-11-22 KST. 사용자가 제공한 **원본 30단계 마스터 프롬프트 012/030(원본 048~050)**에 따라, 이미 예약된 Web Audio 노드의 중단·해제·재시작, 전체 음소거·음량 제어, 모바일 사용자의 오디오 시작 권한 거부·재시도를 검증한다. `schoolband-playtest` 시험 브랜치만 수정하며 운영 `main`, 실제 `baeguindex.com`, Supabase 운영 자료는 유지한다.

## 1. 결함 진단과 실제 수정

### 원래 문제

010·011단계의 오디오 엔진은 각 음색을 `AudioContext.currentTime` 기준 미래 시각에 `OscillatorNode.start(when)`·`AudioBufferSourceNode.start(when)`으로 예약했지만, `finish(true/false)`는 점수 루프와 UI만 중단했다. 따라서 **일부 미래 예약 소리가 사용자 중단 후에도 나올 수 있고**, 컨텍스트·오실레이터·게인·필터를 명시적으로 정리하지 않아 잦은 재시작 시 리소스가 누적될 위험이 있었다.

### 해결 구현

1. `liveAudioVoices` Set 및 `trackAudioSource(source,nodes)`를 추가했다. 오실레이터 일반음, 노이즈 버퍼 음, 드럼 킥, 드럼 탐 등 **네 경로의 모든 소리 소스**를 생성 시 등록한다. `ended` 이벤트 시 관련 `source/gain/filter`를 분리(disconnect)하고 Set에서 제거한다.
2. `stopTrackedAudio()`는 이미 시작되었거나 미래에 예약된 모든 활성 소스에 **`stop(0)`**를 호출하고 이벤트 핸들러·오디오 그래프 연결을 해제한다. `releaseAudioEngine()`은 마스터 게인을 즉시 0으로 차단한 뒤 소스를 정리하고 모든 하위 bus/압축기 노드를 연결 해제, `AudioContext.close()`를 호출하고 오디오 버퍼 참조를 비운다.
3. 정상 곡 종료와 중도 중단 모두 `finish()`에서 이 동일한 release 경로를 탄다. 다음 연주는 새 컨텍스트로 시작하며 이전 컨텍스트의 `statechange`가 새 세션에 영향을 주지 못하게 컨텍스트 식별을 비교한다.
4. 기존 일시정지/백그라운드 감지는 007단계 규칙대로 `AudioContext.suspend()`로 시간축을 함께 멈추되 **일시정지만 했다고 곧바로 예약 소리를 삭제하지 않는다**. 수동 `▶ 이어하기` 이후 동일 노트를 이어서 연주할 수 있다. 일시정지한 상태에서 `■ 중단`하면 정리·close가 실행된다.
5. 모바일의 첫 소리 재생은 `▶ 시작` 사용자의 클릭 흐름에서 `a.resume()`을 호출한다. 거절되면 `NotAllowedError` 등 상세 내부 예외를 화면에 노출하지 않고 컨텍스트를 정리해 `▶ 시작` 버튼을 복구한다. 사용자가 소리 허용 뒤 **다시 직접 눌러** 재시도한다. `startPending`은 연속 탭/비동기 중복 시작으로 컨텍스트가 2개 생기지 않도록 한다. 지원하지 않는 오디오 브라우저에서는 실패를 안내하고 실행하지 않는다.
6. **전체 볼륨 설정**은 0~100%·5% 단위 슬라이더로 추가했다. 마스터 bus에 곡·반주·타격음 전체에 적용한다. `🔇 소리 끄기`는 볼륨 설정과 독립되어 `masterGain=0`으로 우선하며, 음소거를 풀면 기존 볼륨을 복원한다. 설정은 브라우저에 **정수 볼륨 1개만 로컬 저장**한다. UI가 추가되어도 320px 가로 넘침이 생기지 않도록 작은 가로 패널로 배치한다.
7. 실제 사용자 화면에는 오디오 기술 디버그 로그를 노출하지 않는다. `getAudioLifetime()` 진단은 `activeVoices`, 누적 created/ended/cancelled/disconnected, contextsCreated/Closed, peakVoices, volumePercent, muted, masterGain, pendingStart 등을 **숫자/상태 사본**으로 제공하며 학교·학급·학생·실제 음원 식별자를 포함하지 않는다.

### 중요한 미완료 구분

`AudioContext.close()` 호출이 성공한 것과 **현실의 휴대전화 스피커로 유령 소리가 물리적으로 들리지 않는 것**은 다른 검증이다. CI에서는 실제 Chromium Web Audio의 예약 소스·재생 중 소스의 `stop(0)`, disconnect, Context closed, 재생 중지 후 소스 생성 0과 점수·화면 정상 복구를 검사한다. 스피커로 직접 귀에 들리는 유령 소리, iOS/Android 권한 팝업, 블루투스 오디오 지연·문제는 실제 기기에서 검증할 때까지 남긴다(027단계).

## 2. 테스트·완료 기준

- `scripts/test-schoolband-stage012.cjs`: 게임 JS 문법, 네 종류의 AudioScheduledSourceNode 추적 경로, 정상/비정상 중단 release, 오디오 시작 실패의 자원 정리, 음량 0~100% 5단위와 로컬 저장 데이터 경계를 확인한다.
- 실제 데스크톱/320px 모바일 Chromium 각각 **4악기(guitar/drums/bass/keys)**를 연주 시작 후 **미래에 발음할 노트가 실제 `source.start(when)`으로 예약된 상태**에서 중단한다. 예약된 각 소스에 `stop(0)`가 기록되고 disconnect되며 AudioContext 상태가 `closed`가 되는지 확인한다. 350ms 지나도 새로운 예약/출력 소스가 생기지 않아야 한다.
- 자연 종료된 오디오 노드에 `ended` 콜백이 도착해 활성 집합에서 제거되는지, 일시정지 중 스케줄·음원이 유지되는지, 정지된 상태에서 중단하면 전부 해제되는지 검증한다.
- 기본 음량 100%, 35% 설정/재로딩 복원, 0% 무음, 전체 음소거 상태에서 볼륨 60%로 바꿔도 최종 0 유지, 음소거 해제 후 최종 볼륨 48%(master 0.8×0.6)를 다시 얻는지 확인한다.
- 실제 Chromium의 `AudioContext.resume()`이 **첫 시도에 `NotAllowedError`를 거절하도록 시험 주입**하여 시작이 차단되고 새 사용자 클릭으로 정상 재시도되는지 확인한다. Web Audio 자체가 없는 환경도 오류 안내와 버튼 복구를 검증한다.
- CI `.github/workflows/schoolband-stage012.yml`: 신규 검증 → 기존 011단계 48개 오디오 PCM·8마디 코드·4버스 수치 → 010단계 모든 악기 음색/무음 MISS → 007단계 타이밍 일시정지/회복 및 009·005 차트/판정 회귀를 실행한다.
- 데이터·오디오 장치가 공유되는 교실 태블릿 환경에서 **개인별 지문이나 소리 권한의 사용 이력**을 서버에 기록하지 않으며, 실제 교가 저작물을 다운로드·사용하지 않는다.
