# Google Drive 백업 작업자 인증 준비 (실행 금지)
- Google Drive의 소유자 전용 폴더는 생성 확인됨. 이 문서의 후보는 운영 백업이나 파일 업로드를 수행하지 않는다. ChatGPT 연결 권한을 별도 작업자가 재사용할 수 있다고 가정하지 않는다.
- 사용자가 자신의 Google Cloud 프로젝트에서 Drive API 및 필요한 Picker API를 활성화하고 OAuth 데스크톱 클라이언트를 생성한다. 공식 OAuth 라이브러리의 시스템 브라우저/loopback redirect/PKCE 및 offline consent를 사용한다. refresh token 장기 사용 정책(외부 테스트 앱의 만료 등)을 확인한다. Google 공식 데스크톱 OnePick 방식의 최초 인증·선택 후보를 추가했다. 실제 사용자 계정에서의 검증은 아직 하지 않았다.
- drive.file 최소 권한만 요청하며 기존 폴더는 해당 OAuth 앱에서 Picker로 명시 선택/승인한다. 폴더 ID를 입력하는 것만으로 접근권이 생기지 않는다. 사용자의 My Drive 소유자 계정이 필요하다. 공유/서비스계정 추가, 전체 Drive 권한으로의 자동 확대는 금지.
- 실제 폴더 ID와 소유자 permission ID는 승인한 OAuth 계정의 folder metadata/permissions로 독립 확인 후 비공개 설정에 고정한다. 새 앱의 접근 가능 여부는 아직 미확인.
- 신뢰된 검증 checkout 외부의 사용자 전용 0700 디렉터리에 0600 OAuth JSON(schema, folder_id, owner_permission_id, client_id, client_secret, refresh_token) 및 별도 32-byte AES key 파일 보관. 공개 Git, GitHub artifact, 채팅, 콘솔 출력에 저장 금지. 실제 운영 인증정보/키는 이 단계에서 생성하거나 요청하지 않는다. 키 파일은 별도 암호화 키 보관소에 복구 사본을 두고 접근을 분리한다. 키 분실 시 복원 불가, 키 회전 시 기존 백업 복원 키 보존.
- reviewed local script: python3 scripts/release-manager/integrated_drive_setup.py init-key --key-file /PRIVATE/backup.key (기존 파일 덮어쓰기 거부). python3 scripts/release-manager/integrated_drive_setup.py preflight --key-file /PRIVATE/backup.key --oauth-file /PRIVATE/oauth.json (explicit local setup only; OAuth refresh와 고정 폴더 metadata/permissions GET 외에 네트워크 동작 금지). 토큰 scope 정확 일치 확인, 권한 확인, 실제 업로드나 운영 승인과 구분. 실제 사용자 실행은 별도 승인 후 진행. 합성 데이터 전송 검증 필요.
- 별도 reader/worker 프로세스, 서명 관측자, 실제 업로드·장기 저장·복원 검증은 미연결. 같은 Google 소유자 계정의 두 토큰은 독립 보안 주체가 아니다. 운영 transport gate와 fixture-only vault 유지.
- 공식 참조: https://developers.google.com/identity/protocols/oauth2/native-app , https://developers.google.com/workspace/drive/api/guides/api-specific-auth , https://developers.google.com/workspace/drive/picker/guides/desktop-mobile-picker .

## 최초 로그인과 폴더 선택 통합 후보
- Google 데스크톱 OnePick (trigger_onepick=true, prompt=consent, drive.file 단일 scope, file_ids 및 allow_folder_selection) 공식 흐름 사용. 별도의 Picker 웹 앱 또는 API key UI 불필요. Google Cloud 프로젝트, Drive API·Picker API 활성화, Desktop OAuth client 생성은 여전히 선행 조건. https://developers.google.com/workspace/drive/picker/guides/desktop-mobile-picker
- reviewed checkout에서 `python3 scripts/release-manager/integrated_drive_enroll.py --desktop-client-file /PRIVATE/client.json --folder-id SELECTED_FOLDER_ID --oauth-file /PRIVATE/oauth.json --key-file /PRIVATE/backup.key` 실행 후보. 폴더 ID는 승인된 기존 폴더로 제한. client.json은 Google Cloud에서 발급한 Desktop OAuth JSON, 파일 권한 0600, 디렉터리 0700, checkout 외부. 공개 코드에는 실제 ID/인증정보 없음.
- 시스템 브라우저 로그인 및 폴더 선택 1회, PKCE S256/state/127.0.0.1 콜백, 정확한 선택 ID 및 scope 검증, owner-only 메타데이터 확인, refresh token 재검증 후 private config·키 생성. 기존 키는 검증 후 보존하고 기존 OAuth 설정은 덮어쓰지 않음. 인증만 하고 파일 전송하지 않음. 실제 OnePick 연결과 장기 토큰 사용 가능 여부, 독립 관측자, 운영 백업/복원은 미확인. 공개 CI는 합성 테스트만 실행.
