# Google Drive 백업 작업자 인증 준비 (실행 금지)
- Google Drive의 소유자 전용 폴더는 생성 확인됨. 이 문서의 후보는 운영 백업이나 파일 업로드를 수행하지 않는다. ChatGPT 연결 권한을 별도 작업자가 재사용할 수 있다고 가정하지 않는다.
- 사용자가 자신의 Google Cloud 프로젝트에서 Drive API 및 필요한 Picker API를 활성화하고 OAuth 데스크톱 클라이언트를 생성한다. 공식 OAuth 라이브러리의 시스템 브라우저/loopback redirect/PKCE 및 offline consent를 사용한다. refresh token 장기 사용 정책(외부 테스트 앱의 만료 등)을 확인한다. Google 공식 데스크톱 OnePick 방식의 최초 인증·선택 후보를 추가했다. 실제 사용자 계정에서의 검증은 아직 하지 않았다.
- drive.file 최소 권한만 요청하며 기존 폴더는 해당 OAuth 앱에서 Picker로 명시 선택/승인한다. 폴더 ID를 입력하는 것만으로 접근권이 생기지 않는다. 사용자의 My Drive 소유자 계정이 필요하다. 공유/서비스계정 추가, 전체 Drive 권한으로의 자동 확대는 금지.
- 실제 폴더 ID와 소유자 permission ID는 승인한 OAuth 계정의 folder metadata/permissions로 독립 확인 후 비공개 설정에 고정한다. 새 앱의 접근 가능 여부는 아직 미확인.
- 신뢰된 검증 checkout 외부의 사용자 전용 0700 디렉터리에 0600 OAuth JSON(schema, folder_id, owner_permission_id, client_id, client_secret, refresh_token) 및 별도 32-byte AES key 파일 보관. 공개 Git, GitHub artifact, 채팅, 콘솔 출력에 저장 금지. 실제 운영 인증정보/키는 이 단계에서 생성하거나 요청하지 않는다. 키 파일은 별도 암호화 키 보관소에 복구 사본을 두고 접근을 분리한다. 키 분실 시 복원 불가, 키 회전 시 기존 백업 복원 키 보존.
- reviewed local script: python3 scripts/release-manager/integrated_drive_setup.py init-key --key-file /PRIVATE/backup.key (기존 파일 덮어쓰기 거부). python3 scripts/release-manager/integrated_drive_setup.py preflight --key-file /PRIVATE/backup.key --oauth-file /PRIVATE/oauth.json (explicit local setup only; OAuth refresh와 고정 폴더 metadata/permissions GET 외에 네트워크 동작 금지). 토큰 scope 정확 일치 확인, 권한 확인, 실제 업로드나 운영 승인과 구분. 실제 사용자 실행은 별도 승인 후 진행. 합성 데이터 전송 검증 필요.
- 별도 reader/worker 프로세스, 서명 관측자, 실제 업로드·장기 저장·복원 검증은 미연결. 같은 Google 소유자 계정의 두 토큰은 독립 보안 주체가 아니다. 운영 transport gate와 fixture-only vault 유지.
- 공식 참조: https://developers.google.com/identity/protocols/oauth2/native-app , https://developers.google.com/workspace/drive/api/guides/api-specific-auth , https://developers.google.com/workspace/drive/picker/guides/desktop-mobile-picker .

## 최초 로그인과 폴더 선택 통합 후보
- Google 데스크톱 OnePick (trigger_onepick=true, prompt=consent, drive.file 단일 scope, file_ids 및 allow_folder_selection) 공식 흐름 사용. 별도의 Picker 웹 앱 또는 API key UI 불필요. Google Cloud 프로젝트, Drive API·Picker API 활성화, Desktop OAuth client 생성은 여전히 선행 조건. https://developers.google.com/workspace/drive/picker/guides/desktop-mobile-picker
- reviewed checkout에서 `python3 scripts/release-manager/integrated_drive_enroll.py --desktop-client-file /PRIVATE/client.json --folder-id SELECTED_FOLDER_ID --oauth-file /PRIVATE/oauth.json --key-file /PRIVATE/backup.key` 실행 후보. 폴더 ID는 승인된 기존 폴더로 제한. client.json은 Google Cloud에서 발급한 Desktop OAuth JSON, 파일 권한 0600, 디렉터리 0700, checkout 외부. 공개 코드에는 실제 ID/인증정보 없음.
- 시스템 브라우저 로그인 및 폴더 선택 1회, PKCE S256/state/127.0.0.1 콜백, 정확한 선택 ID 및 scope 검증, owner-only 메타데이터 확인, refresh token 재검증 후 private config·키 생성. 기존 키는 검증 후 보존하고 기존 OAuth 설정은 덮어쓰지 않음. 인증만 하고 파일 전송하지 않음. 실제 OnePick 연결과 장기 토큰 사용 가능 여부, 독립 관측자, 운영 백업/복원은 미확인. 공개 CI는 합성 테스트만 실행.

## Mac 실제 합성 데이터 리허설
- 사용자 보고: OnePick 인증 결과 oauth_scope_verified/folder_private/local_key_present true, actual_upload_verified/execution_enabled false. 비밀값 미수집.
- integrated_drive_rehearsal.py는 Mac에서 새 SQLite 합성 3행을 만들고 별도 임시 키로 암호화하여 승인된 Drive 폴더에 1회 업로드, 실제 내려받은 바이트를 복호화하여 격리 SQLite에서 스키마/행/무결성을 비교한다. DB 연결 인수 없음, 기존 키는 읽기 검증만, 원격 삭제/업데이트/자동 재시도 금지. 합성 원격 파일은 남으며 임시 키는 보존하지 않는다(리허설 후 복호화 불가). 실패 시 원격 객체가 남을 수 있으므로 재실행 전 폴더 확인. PostgreSQL 실제 원격 복원 및 독립 관측자 검증으로 간주하지 않는다.
- 실제 전송은 사용자 Mac에서 명시적으로 --confirm-synthetic-upload 선택 시에만 수행. 공개 CI는 Fake transport만 사용. 운영 실행 잠금 유지.

- 첫 실제 Mac 리허설은 일반 실패 출력으로 종료되었다(사용자 보고). 이후 연결된 Drive의 읽기 전용 폴더 목록은 0건이고 폴더 shared=false. 원인 단정 및 자동 재시도 금지. 새 --preflight-only는 로컬 합성 vault 생성, 토큰 갱신, 폴더 메타데이터/권한 GET만 수행한다. 실패 출력은 고정 phase/reason만 포함하며 원본 예외/응답/경로/비밀값을 출력하지 않는다. 원격 쓰기 여부는 보수적으로 표시한다.

- 실제 Mac 재검증 결과 drive_invalid_upload_session (사용자 보고). 정확한 Location 원문은 수집하지 않는다. 합성 512KiB 이하 파일에만 Google Drive multipart/related 단일 POST를 적용하여 세션 URI 의존을 제거한다. 기존 resumable 어댑터 및 운영 잠금은 변경하지 않는다. 성공 여부는 실제 Mac 재검증으로만 확정한다. 원격 수정/삭제/자동 재시도 없음. 재실행 전에 독립 폴더 목록 확인 필요.

## 실제 SQLite 검증 및 격리 PG17 후보
- b7f5df0 Mac 사용자 보고: scope=synthetic_sqlite_only, encrypted_upload_verified/download_verified/fixture_restore_verified=true, fixture_rows=3, production_backup_executed/independent_observer_verified/execution_enabled=false. SHA256=0f04dacf823e8e6dd81dadc7a38be7e0dec456cfe19df6737d47935fa157ac7f (합성 데이터 해시만 기록).
- 연결된 Drive 검색 결과는 0건이었으나 직접 폴더 하위 페이지 조회에서 동일 해시 이름의 9085-byte vault 1개 확인. 별도 파일 메타데이터 조회로 지정 폴더, shared=false, owner-only 확인. 검색과 직접 목록 차이의 내부 원인은 미확정. 원격 바이트 독립 서명은 미확인. 폴더/파일 ID 및 개인 계정 정보는 공개 저장소에 기록하지 않음.
- integrated_drive_pg_rehearsal.py: 기존 FixtureCluster(17)로 새 network=none PostgreSQL 컨테이너만 생성, 내부 고정 SQL 6행, schema/rows/sequence/RLS 비교, 임시 키로 암호화, 기존 소형 multipart 경로에 연결, 실제 내려받은 bytes만 새 fixture_restore로 pg_restore. 공개 CI는 Fake Drive만 사용한다. 운영 연결 문자열 및 임의 dump 입력 없음. Mac 실행은 로컬 Docker 엔진 /var/run/docker.sock 필요; 기존 Docker 컨테이너 및 운영 DB 사용 금지. 실제 원격 PG17 검증 미완료. 기존 운영 proof verifier에는 연결하지 않는다.
- 관측자 분리: 직접 폴더 목록/메타데이터 확인은 별도 조회이지만 같은 소유자 계정일 수 있으며 서명된 독립 관측 증거가 아니다. 다음 단계는 별도 읽기 전용 관측자와 신뢰키, 원격 암호문 bytes 및 해시/복원 결과 결합 검증, freshness/job/plan scope 결합. 소유자 전용 폴더 권한 유지; 사용자 승인 없는 공유/권한 확대 금지. 기존 운영 proof gate는 그대로 유지하며 합성 proof를 운영 승인으로 승격 금지.

- integrated_drive_fixture_observer.py: 별도 실행 프로세스의 고정 file ID/hash와 OAuth 설정으로 GET만 허용, 지정 folder/owner/size/SHA256과 실제 내려받은 암호문 재검증. 키를 읽거나 복호화하지 않으며 독립 주체/복원/운영 proof는 항상 false. 별도 신뢰 주체·서명 연결은 아직 미완료. 기존 integrated_production_entry의 생산 증거 scope를 변경하지 않는다. 공개 CI는 가짜 토큰/HTTP만 사용.

## 합성 관측 서명 프로토콜 후보
- integrated_fixture_attestation.py는 고정 challenge(256-bit)/candidate SHA/plan hash/file ID/folder ID/ciphertext hash를 실제 read-only observe 결과와 묶어 domain-separated Ed25519 서명한다. 독립적으로 고정된 공개키로 서명·정확한 pins·30분 freshness 검사. challenge의 1회 소비는 아직 통합 관제탑 외부 trust registry의 과제이며 서명 검증만으로 독립 신원/운영 승인/복원 증거가 되지 않는다. 합성 scope 및 false 운영 플래그 강제. 실제 키 발급·분리 보관/별도 Google 주체·운영 연결은 미완료. CI ephemeral 키/가짜 HTTP만 사용. 운영 검증기 및 gate 변경 없음.
