2026-11-22 KST. 원본 마스터 프롬프트 017/030(원본 064~067) 기준. 시험 브랜치 schoolband-playtest만 수정하며 운영 main·baeguindex.com·Supabase 운영 환경은 변경하지 않는다.

## 실제 적용

- PC와 Android 스타일 브라우저에서 3·4·5개 레인 터치 버튼을 각각 독립 입력으로 판정하도록 포인터 ID→레인 Map을 관리한다. 실제 브라우저 신뢰 입력에만 포인터 소유권을 기록하고, 같은 손가락으로 중복 타격하지 못하도록 한다. 손가락을 놓을 때, 취소될 때, 캡처가 풀릴 때, 회전하거나 악기를 바꿀 때·연주 종료 시 소유권을 해제한다. 기존 008단계의 기본 pointerId=0 합성 입력 및 키보드 Enter 조작은 계속 지원한다.
- 터치 패드는 touch-action:none으로 제스처 충돌을 줄이고 각 레인의 **이름·키 문자**를 항상 표시한다. 색상만으로 레인을 구별하도록 요구하지 않는다.
- 가로 화면(너비 550px 이상, 높이 500px 이하)은 노트 캔버스와 3~5개 터치 패드를 좌우 두 열에 배치, 세로 화면은 기존 위·아래 구조다. resize/orientationchange 이벤트에서 동일 오디오 시계와 점수는 보존하고 화면만 다시 그린다. 실제 모바일 OS 회전과 자동화 viewport 변경은 서로 구별한다.
- 큰 글씨 및 고대비 사용자는 화면 자체에서 설정할 수 있다. 큰 글씨에서 레인 제목 13px 이상, 고대비 모드에서 검정 바탕·흰 테두리·노란 키 레이블을 사용하고 OS prefers-contrast:more 설정을 반영한다. 표시 설정만 로컬 브라우저에 저장한다.
- 전체화면 버튼은 사용자 클릭에서 Fullscreen API를 요청하고 실제 document.fullscreenElement 상태를 기준으로만 토글된다. 거절 또는 미지원 시 일반 화면을 유지하면서 접근성 상태 메시지로 알린다.
- 전체 화면의 API 호환성 여부와 터치 위치·사이즈는 읽기 전용 QA 진단 함수 getMobileUiState()로 확인한다. 학생·교사/실제 교가 관련 데이터는 담지 않는다.

PC 1280px 및 모바일 320·375px Chromium에서 4악기 레인 이름/키·실제 너비/높이, 가로 오버플로, 큰 글씨 및 고대비 스타일·저장, 전체화면 거절 복귀, 실제 Chromium CDP Input.dispatchTouchEvent 다중터치, 사용 중 가로/세로 회전 후 재생·점수 유지, 중단/재시작, 키보드 초점 유지 검증. Stage016 3화면과 Stage008 40회 키/터치, Stage005/007 타이밍을 회귀검사.

실제 물리 Android/iOS 기기에서 동시 손가락 입력·스피커·OS 전체화면·화면 회전·TalkBack·VoiceOver를 사용한 인간 검수는 아직 수행하지 않았으며 027단계 실기 확인 대상으로 남긴다.
